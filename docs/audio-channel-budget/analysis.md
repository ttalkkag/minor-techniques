# 제한된 음원 채널과 음악 저장 공간 배분하기

[주제 요약](README.md) · [리서치](research.md)

## 채널 수와 스피커 수는 다르다

Game Boy의 두 펄스·파형·노이즈는 소리를 만드는 하드웨어 음원 채널이다. 좌우 스테레오는 그 소리를 어느 출력으로 보낼지의 구분이다. 채널이 네 개라는 말이 좌우 출력 두 개와 모순되지 않는다.

파형 채널에는 32개의 4비트 표본이 들어간다. 그래서 “Game Boy는 전부 수식 합성, 다음 기종은 전부 녹음 재생”으로 나누면 실제 기능을 단순화한다. 이 사양의 근거는 제조사 명세가 아닌 하드웨어 연구 프로젝트 Pan Docs다. [Audio Registers](https://raw.githubusercontent.com/gbdev/pandocs/master/src/Audio_Registers.md)

## 효과음이 음악을 밀어내는 과정

교육용 네 채널 시퀀서에서 Pulse 1=멜로디, Pulse 2=화음, Wave=베이스, Noise=리듬으로 배정했다고 하자. 효과음도 Noise가 필요하면 동시에 같은 채널을 독립적으로 차지할 수 없으므로 우선순위를 정해야 한다.

1. 효과음 요청의 우선순위·필요 채널·길이를 확인한다.
2. 음악보다 중요하면 해당 채널의 출력을 효과음에 넘긴다.
3. 음악의 논리적 곡 시계는 계속 진행한다.
4. 효과음 종료 시 과거에 끊긴 음의 시작으로 돌아가지 않고 현재 곡 위치에 맞는 음악 상태를 채택한다.

| 정책 | 효과음 | 음악의 손실 |
|---|---|---|
| 낮은 우선순위 요청 거부 | 일부 효과음을 못 들음 | 기존 음악 유지 |
| 음악 채널 선점 | 효과음이 명확함 | 특정 악기가 잠시 빠짐 |
| 오래된 효과음 선점 | 최신 사건을 강조 | 앞 효과음이 잘림 |
| 소프트웨어로 합산 | 더 많은 소리를 표현할 여지 | CPU·음질·믹싱 비용 추가 |

채널 배분의 자체 예제다. 특정 포켓몬 드라이버가 이 표대로 동작했다는 분석은 하지 않았다. 정확한 칩 에뮬레이션도 별도 범위다.

## 저장 데이터의 종류를 공정하게 비교하기

음표 시퀀스는 언제 어떤 악기를 어떤 음으로 연주할지의 명령이다. PCM은 시간에 따른 표본이다. 시퀀스 쪽은 공유 악기 샘플, 명령, 메타데이터를 모두 더해야 하며 명령만 비교하면 유리하게 왜곡된다.

비압축 PCM 데이터량은 `초 × 샘플레이트 × 표본당 저장 비트 수/8 × 저장 채널 수`다. 여기서 채널은 파일에 저장한 모노·스테레오 등의 채널이며, 재생 장치의 출력 채널 수와 반드시 같지는 않다. 60초·48kHz·16비트·스테레오는 11,520,000바이트다. 헤더와 압축은 제외했다. [PCM 형식의 채널·바이트율 규약](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/ns-mmeapi-waveformatex) 자체 비교 예에서 시퀀스 명령 4,000바이트와 악기 샘플 200,000바이트를 쓰면 204,000바이트지만 두 방식의 음색·잔향·충실도가 동일하다는 보장은 없다.

완성 음원을 저장하면 연주 중 합성 부담을 줄일 여지가 있으나 스트리밍·디코딩·버퍼 예산이 남는다. 시퀀스는 게임 상태에 맞춘 악기 제어가 쉬울 수 있으나 악기 뱅크와 재생기가 필요하다.

## 샘플 하나로 여러 음을 낼 때

단일 샘플을 읽는 속도만 바꾸는 예제에서 반음 차이가 s면 재생 비율 r=2^(s/12)다. 반복·중간 정지 없이 전체 샘플을 일정한 양수 r로 재생하면 길이는 D/r다. 한 옥타브 높이는 s=12, r=2이므로 길이는 절반이다. 길이를 유지한 채 음높이만 바꾸려면 별도 처리가 필요하다. [Web Audio 1.0 재생률 규약](https://www.w3.org/TR/webaudio-1.0/#dom-audiobuffersourcenode-playbackrate)

DS도 샘플 재생 전용으로 설명하지 않는다. libnds의 공개 API에는 샘플 외에 PSG와 노이즈가 있다. [libnds sound.h](https://github.com/devkitPro/libnds/blob/master/include/nds/arm9/sound.h) 이 기능 목록은 모든 출시 게임이 무엇을 썼는지 알려 주지는 않는다. CPU가 나뉘었다는 사실도 모든 자원 경쟁이 사라졌다는 증거가 아니다.

## 실험으로 보여 줄 차이

자작 멜로디의 각 채널 소유자와 곡 시계를 표시하고 효과음 우선순위·길이·동시 채널 수를 조절한다. 저장 크기는 시퀀스와 악기 데이터, PCM 조건을 나눠 표시한다. 음높이 변경에서 길이가 함께 변하는 파형을 보여 주면 샘플 재생의 절충도 드러난다.

원곡 청취나 칩 실행, 실제 기종 간 성능 비교는 하지 않았다. 합성음만으로 재현할 수 있는 자원 배분과 데이터 표현을 우선 설명한다.
