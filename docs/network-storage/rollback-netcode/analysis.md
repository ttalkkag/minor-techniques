# 예측이 틀렸을 때 상태를 복원하는 롤백

[그룹 요약](../README.md) · [리서치](research.md)

## 지연을 숨기려면 무엇을 가정해야 하나

내 입력을 즉시 적용할 때 상대의 같은 틱 입력은 아직 도착하지 않을 수 있다. 입력을 기다리는 방법은 반응 시간을 늘린다. 롤백은 임시 입력으로 먼저 진행하고 실제 입력과 다르면 그 계산을 다시 한다.

게임 상태를 틱 시작의 S[k], 양쪽 입력을 I[k]라고 정의하면 한 틱은 `S[k+1] = F(S[k], I[k])`다. 같은 상태와 입력에 F가 다른 결과를 내면 재실행해도 원래 결과를 복구할 수 없다. 그림·소리의 재생 상태와 게임 결과를 바꾸는 상태를 나누는 이유다. [GGPO 동작 원리](https://www.ggpo.net/)

## 틱 100의 입력이 늦게 온 예

| 단계 | 보유 정보 | 수행한 일 |
|---|---|---|
| 틱 100 시작 | 상대 입력 미도착 | S[100] 저장, 직전 방향 유지로 예측 |
| 틱 100–103 | 예측 입력으로 진행 | 현재 화면은 S[104] |
| 입력 도착 | 실제 I[100]은 공격 | 처음 틀린 틱 100 확인 |
| 복원 | 저장해 둔 S[100] | 수정한 I[100]부터 I[103]까지 계산 |
| 표시 | 수정된 S[104] | 최종 상태를 한 번 표시 |

공격 시작 4틱을 화면에 각각 보여 주지 않고 S[104]로 바뀌면 상대의 공격 초반이 빠져 보일 수 있다. 원인은 모션을 잘라 붙였기 때문이 아니라 과거 계산을 다시 한 뒤 현재 결과를 표시했기 때문이다.

## 복원할 상태와 재실행하지 않을 일

복원 상태에는 위치·속도 외에도 체력, 공격 진행 틱, 쿨다운, 이미 맞힌 대상, 난수 생성기 상태 등 다음 결과에 영향을 주는 값을 넣는다. 렌더러의 텍스처와 변하지 않는 자산까지 매 틱 복사할 필요는 없다.

GGPO 개발 가이드는 직렬화 가능한 상태, 렌더링 없이 한 틱 진행하는 함수, 결정론, 고정 틱을 통합 조건으로 설명한다. 현재 벽시계·숨은 전역 변수·복원하지 않은 난수 상태가 결과를 바꾸는 문제를 지적한다. [GGPO Developer Guide](https://github.com/pond3r/ggpo/blob/master/doc/DeveloperGuide.md)

교육용 효과 처리에서는 `(틱, 행위자, 이벤트 순번)`을 식별자로 사용할 수 있다. 같은 발사 소리를 재계산할 때 재생 요청까지 매번 보내면 겹쳐 들린다. 이미 표시한 예측 효과가 수정된 세계에서 사라진 경우는 취소·마무리·그대로 종료 중 하나의 정책이 필요하다. 식별자만으로 틀린 효과를 자동 되돌릴 수는 없다. 보상처럼 외부로 확정하는 일은 게임의 확정 조건을 만족한 뒤 처리한다.

## 비용과 입력 지연의 절충

틱당 상태 크기를 B, 저장 틱 수를 K로 두면 단순 전체 복사 모델의 메모리는 대략 B×K다. 늦은 입력으로 r틱을 다시 계산하고 한 틱 계산이 c초라면 재실행 비용은 대략 r×c초다. 렌더링 비용은 매 재실행 틱에 넣지 않아도 되지만 게임 규칙 계산은 반복해야 한다.

입력 지연을 조금 두면 예측해야 할 틱이 줄 수 있다. 너무 오래 입력이 없으면 저장·예측 범위를 무한히 늘리는 대신 기다리거나 연결 정책을 적용한다. 큰 롤백이 항상 눈에 보이지 않는다는 보장은 없다. 격투 게임의 작은 결정론적 상태와 거대한 비결정적 월드의 통합 난이도는 다르다.

## 확인할 장면과 경계

관찰안은 두 가상 클라이언트에 같은 틱 입력을 주고 한쪽 전달만 늦추는 것이다. 예측값·실제값·복원 틱·재실행 횟수를 표시하면 영상의 생략된 동작을 보여 줄 수 있다. 모든 입력이 확정된 같은 틱에서 상태를 비교해야 하며, 서로 다른 현재 틱의 해시를 비교하면 잘못된 불일치가 된다.

해시는 불일치를 찾는 진단 수단이다. 같은 브라우저 안에서 결과가 같아도 다른 CPU·플랫폼·컴파일 설정의 결정론이나 실제 인터넷의 품질을 증명하지 않는다. 이 문서는 실행 결과를 기록한 문서가 아니다.
