## 조사 이력과 자료

수집 ID는 `rollback-netcode`다. 09-22 수집·보완, 09-23 통합 검토를 거쳐 2026-09-25에 영상의 관련 자막과 GGPO 본문을 재열람했다. 코드 통합이나 네트워크 실행은 하지 않았다. 과거 시각 검토는 대표 화면 수준이다. 아래의 공개 영상 시점과 개발 가이드에서 결과 묘사와 알고리즘을 구분한다.

## 영상의 결과 묘사와 알고리즘

[영상 00:18](https://www.youtube.com/watch?v=kap1_O66XCY&t=18s)은 입력을 기다리는 딜레이 방식을, [00:33–00:42](https://www.youtube.com/watch?v=kap1_O66XCY&t=33s)는 늦은 입력 도착 후 공격 초반 모션이 생략되는 모습을 설명한다.

자막의 00:35 이후 설명만 읽으면 상대 애니메이션의 재생 위치만 바꾸는 기법처럼 보인다. 기존 분석이 추가한 상태 저장·복원·입력 재실행을 유지했다. 00:44의 눈치채지 못한다는 표현도 모든 지연과 장면에 적용하지 않는다. 이 두 제한이 기존 `qualified` 판정의 핵심이다.

## 이 문서에서 새로 구성한 설명

틱 100–103의 표, S[k]를 틱 시작 상태로 정의한 수식, 이벤트 식별자는 교육용 설명이다. GGPO 예제 프로그램을 실행해서 얻은 로그가 아니다. 특히 효과의 중복 방지·취소 정책은 게임마다 정해야 하므로 하나의 식별자 방식이 모든 부작용을 해결한다고 쓰지 않는다.

현재 과거 판정과 롤백을 같은 되감기로 섞지 않았다. [지연 보상 분석](../lag-compensation/analysis.md)은 사격 질의 시점을 고르는 문제이고, 이 문서는 게임 규칙을 입력 이력으로 재실행하는 문제다.

## 추가 조사 과제

원작의 스냅샷 구조, 입력 예측 규칙, 최대 예측 길이는 확인하지 않았다. 실제 구현 전에는 상태 누락을 찾는 재실행 비교와 외부 효과 확정 조건을 정해야 한다. 플랫폼 간 결정론과 실제 패킷 손실에서의 복구는 각각 별도 실행 근거가 필요하다.
