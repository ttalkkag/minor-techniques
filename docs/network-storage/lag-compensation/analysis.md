# 사수 화면과 서버 현재가 어긋나는 지연 보상

[그룹 요약](../README.md) · [리서치](research.md)

## 시간차를 위치 오차로 바꾸어 보기

서버가 명령을 처리할 때 사수는 이미 이전 상태를 보고 발사했다. 그 화면에는 전달 지연뿐 아니라 부드럽게 움직이도록 표시를 늦추는 보간량도 들어갈 수 있다. 모든 차이를 RTT/2로 놓으면 편도 지연이 다르거나 표시 보간량이 있는 경우 틀린다.

교육용 예로 서버 시각 10.000초의 표적을 사수 화면에 표시했다고 하자. 사수의 입력이 서버에서 처리되는 시각은 10.120초다. 표적이 그 사이 5m/s로 직선 이동했다면 현재 위치와 화면의 위치는 0.6m 차이 난다. 명중 반경보다 차이가 크면 화면 중앙에 겨냥해도 현재 상태 검사에서는 빗나간다. 이 예제는 시계 정렬이 이미 된 가상 모델이다.

## 되감는 대상과 시간 정하기

1. 틱별로 사격 판정에 필요한 충돌체 위치·회전·자세를 이력에 저장한다.
2. 명령의 순서와 발사 가능 상태를 검증한다. 발사 시각은 서버가 인정할 수 있는 시간 기준으로 해석한다.
3. 허용 이력 안의 질의 시각 q를 정한다. 과도하게 오래된 시각을 거부할지 경계 시각으로 제한할지 규칙을 정한다.
4. q를 사이에 둔 두 틱의 과거 충돌체를 구한다. 연속 이동이라면 위치 보간을 할 수 있다. 순간이동·생성·파괴는 연속 보간할 수 없는 사건으로 처리한다.
5. 과거 상태에서 광선을 검사하고 결과를 확정한다. 현재 충돌체를 임시 이동시켰다면 검사 종료 후 현재 상태를 복구한다.

예를 들어 60Hz 이력에서 10.000초와 약 10.016667초 사이의 10.010초를 질의하면 위치의 선형 보간 계수는 약 0.6이다. 이는 두 틱 사이 정밀도를 높이는 계산이며 네트워크의 전달 시간을 줄이지 않는다. 회전과 애니메이션 자세는 해당 표현에 맞는 복원이 필요하다.

## 움직이는 엄폐물을 섞으면 생기는 오류

q에서는 문이 열려 있었는데 현재는 닫혔다고 하자. 플레이어만 q로 되돌리고 문은 현재 상태로 검사하면, 서로 동시에 존재한 적 없는 장면을 만들 수 있다. 역으로 과거에는 닫힌 문을 현재 열린 상태로 쓰면 벽을 통과한 판정이 된다.

Photon Fusion의 `IncludePhysX`는 일반 Unity Collider를 현재 상태로 조회한다. 따라서 움직이는 일반 Collider와 과거 Hitbox를 한 질의에 섞는 경우를 별도로 다뤄야 한다. `SubtickAccuracy`는 과거 두 틱 사이 상태를 더 정확히 찾는 옵션이다. [Fusion의 Queries와 Sub-tick Accuracy](https://doc.photonengine.com/fusion/v2/manual/advanced/lag-compensation)

해당 Fusion 기능의 지원 범위는 Server Mode와 Host Mode다. Shared Mode까지 같은 서버 판정 구조가 제공된다고 해석하지 않는다.

## 이력의 비용과 공정성

이력 크기의 단순 예산은 `대상 수 × 대상당 상태 크기 × 저장 틱 수`로 잡을 수 있다. 100개 대상, 틱당 64바이트, 60Hz로 0.25초를 유지하는 가상 구성은 경계 표본을 제외한 15개 스냅샷에 96,000바이트다. 실제 포즈·인덱스·할당 메타데이터와 경계 표본은 추가된다. 이 값은 어떤 엔진의 실제 사용량도 아니다.

긴 이력은 더 늦은 명령을 판정할 여지를 주지만 피격자가 엄폐 후 맞았다고 느끼는 구간도 넓힌다. 사수와 피격자가 동시에 같은 현재 화면을 보도록 만들 수는 없다. 보상 길이는 기술 설정과 게임 규칙의 선택이다. 유저가 언제나 한 오류를 더 선호한다는 결론은 사용하지 않는다.

Riot의 2020년 공개 설명은 서버가 위치·애니메이션 상태를 발사 프레임으로 복원해 판정하는 사례다. 지금의 내부 상수와 동일함을 확인한 자료는 아니다. [Riot 히트 등록 설명](https://playvalorant.com/en-gb/news/dev/the-state-of-hit-registration/)

## 실험으로 연결할 관찰

사수 화면, 서버 현재, 판정에 사용한 과거 상태를 같은 장면의 세 시간축으로 보여주면 좋다. 편도 지연·보간량·이력 길이를 별도로 조절하고 질의 시각을 표시한다. 위조·중복·이력 초과 명령과 움직이는 문을 포함해야 단순 과거 재생과 판정 규칙의 차이가 드러난다. 실제 네트워크 실험은 아직 수행하지 않았다.
