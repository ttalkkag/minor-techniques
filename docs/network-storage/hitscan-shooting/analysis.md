# 조준점과 총구가 다른 사격 판정

[그룹 요약](../README.md) · [리서치](research.md)

## 문제가 생기는 조건

히트스캔은 발사 시각의 선분과 충돌체를 검사해 명중을 정한다. 화면에 그리는 총알 궤적은 이 검사 결과를 표현하는 효과다. 발사 위치가 카메라라면 조준점과 판정을 맞추기 쉽지만 총구 앞 엄폐물을 놓칠 수 있다. 총구의 정면을 그대로 사용하면 시차 때문에 조준점과 실제 충돌점이 달라진다.

간단한 단면 예로 카메라 높이를 1.7m, 총구 높이를 1.2m, 바로 앞 엄폐물 높이를 1.4m로 놓는다. 카메라의 수평선은 벽 위로 지나고 총구의 수평선은 벽에 닿는다. 같은 캐릭터 위치에서도 출발점이 바뀌면 판정이 달라진다. 이 수치는 이해를 위한 구성값이다.

## 두 검사로 목표와 발사 경로 연결하기

카메라 위치를 C, 정규화한 조준 방향을 d, 조준 탐색 거리를 R로 둔다.

1. C에서 C + R×d까지 검사한다. 첫 충돌점이 있으면 P로 선택하고, 없으면 선분 끝을 P로 사용한다.
2. 총구 M과 P가 같은 점인지 먼저 확인한다. 같다면 정규화할 방향이 없으므로 정해 둔 근접 발사 규칙으로 처리한다.
3. 총구에서 P를 향하는 방향 e = (P−M)/|P−M|를 구한다. 실제 탄환 사거리를 총구 기준으로 제한한다면 최종 선분 길이는 min(|P−M|, 무기 사거리)다.
4. 이 선분의 첫 장애물을 실제 충돌로 채택한다. 벽이 먼저면 벽에서 끝나고, 아무것도 없으면 선분 끝에서 끝난다.
5. 피해·탄착 효과·궤적이 같은 최종 결과를 사용하도록 연결한다.

카메라 탐색 거리와 총구 사거리는 의미가 다르다. 둘을 무조건 같은 끝점으로 처리하면 카메라와 총구 사이 거리만큼 실제 도달 거리가 늘 수 있다. 총구 기준 제한을 쓸지 화면 조준 기준 제한을 쓸지는 무기 규칙으로 고정한다. 위 절차는 이 프로젝트의 교육용 설계이며 모든 FPS가 쓰는 내부 코드라는 주장은 하지 않는다.

## 광선 하나를 더 쏘는 것으로 끝나지 않는 경계

| 조건 | 빠지기 쉬운 처리 | 설명할 결과 |
|---|---|---|
| 자기 몸·무기가 경로에 있음 | 자기 충돌체 제외와 레이어 마스크 | 자기 캐릭터에 먼저 맞는 현상 제거 |
| 총구가 벽 안에 있음 | 시작점의 겹침 확인 | 엔진의 내부 출발 광선 규약에 따라 벽이 누락될 수 있으므로 별도 정책 필요 |
| 목표가 총구 뒤에 있음 | 전방 허용각·근접 판정 | 뒤로 휘어 쏘는 듯한 결과를 허용할지 결정 |
| 발사 후 총구 애니메이션이 이동함 | 발사 시점 좌표 저장 | 판정 시점과 효과 시작점의 차이 구분 |
| 매우 얇은 장식이 앞을 가림 | 시각 메시와 충돌 마스크 구분 | 장식에 맞는지 관통하는지 무기 규칙 유지 |

Godot의 광선 문서는 출발·도착점, 자기 제외, 충돌 마스크, 물리 공간 질의 시점의 API 근거다. 내부 출발점 처리나 위 무기 정책을 자동 해결하는 근거는 아니다. [Godot Ray-casting](https://docs.godotengine.org/en/stable/tutorials/physics/ray-casting.html)

Godot의 `PhysicsRayQueryParameters3D.hit_from_inside`는 기본값이 false다. true로 설정해 내부 출발 충돌을 검출하면 법선은 영벡터이며, 오목 다각형·높이맵에는 이 옵션이 적용되지 않는다. 따라서 옵션 하나로 모든 총구 겹침을 해결한다고 해석하면 안 된다. [Godot 광선 질의 매개변수](https://docs.godotengine.org/en/stable/classes/class_physicsrayqueryparameters3d.html#class-physicsrayqueryparameters3d-property-hit-from-inside)

## 선택 기준과 대가

조준점 일치를 중시하는 무기에는 두 단계 검사가 설명하기 쉽다. 총구의 실제 방향이 중요한 무기나 탄도·비행 시간이 필요한 무기는 다른 설계를 택할 수 있다. 투사체로 바꾸면 중력과 이동 중 충돌을 설명할 수 있지만 이것이 히트스캔의 보편적 개선안은 아니다.

서버 권한과 [과거 판정](../lag-compensation/analysis.md)은 별도 축이다. 클라이언트 화면에서 두 광선이 일치해도 온라인에서 발사 시각·발사 가능 상태를 신뢰할 근거가 되지는 않는다.

## 구현 시 관찰할 장면

카메라·총구·목표·두 선분을 표시하고 엄폐물 높이, 카메라 오프셋, 목표 거리만 독립적으로 바꾸면 원인이 드러난다. 눈만 노출, 총구만 노출, 총구가 벽 내부인 경우를 각각 비교한다. 이 관찰안은 교육용 설계이며 원작 사격 코드를 실행해 얻은 결과가 아니다.
