# 컨트롤러 입력과 게임 메모리의 실행 경계 — 상세 분석

[그룹 요약](../README.md) · [분석](analysis.md) · [리서치](research.md)

고전 게임에서 컨트롤러 입력이 메모리에 저장되고, 잘못된 실행 위치 때문에 그 데이터가 명령으로 해석되면 원래와 다른 게임 동작이 나타날 수 있다. 입력값·메모리 칸·실행 위치를 함께 관찰해 데이터 변경과 제어 흐름 변경의 차이를 설명한다. Triforce% 사례의 공개 설명을 바탕으로 하며 원작 콘솔의 실행을 재현한 결과는 아니다.

## 같은 비트열이라는 설명만으로 부족한 이유

메모리에 숫자를 썼다고 곧바로 명령이 실행되지는 않는다. 실행 위치가 그 영역을 가리키고 환경이 해당 비트열을 명령으로 해석해야 한다. 데이터의 변조와 제어 흐름의 이동은 구분되는 조건이다. 현대 환경의 실행 권한·메모리 보호 여부도 별도로 봐야 한다.

교육용 가상 머신을 생각하면 배열의 앞부분은 명령, 뒷부분은 점수 데이터다. 프로그램 카운터가 정상 명령 범위 안에 있는 동안 점수 값을 바꿔도 숫자만 달라진다. 잘못된 분기로 데이터 영역을 명령처럼 읽는 순간에는 같은 값이 다른 의미를 가진다. 이 예시는 범위·분기·해석의 관계를 설명하는 모형이다.

## 제한된 모형에서 보여 줄 해결책

| 확인할 조건 | 문제 흐름 | 방어를 켰을 때의 기대 |
| --- | --- | --- |
| 쓰기 범위 | 입력이 의도한 데이터 칸을 벗어남 | 허용된 범위 밖 쓰기 거부 |
| 분기 대상 | 점수 영역으로 다음 실행 위치가 이동 | 실행 가능한 영역인지 검사 |
| 명령 해석 | 임의 숫자를 명령으로 읽음 | 허용 명령 집합만 실행 |
| 실행량 | 종료하지 않는 반복으로 화면이 멈춤 | 단계 수·메모리 상한과 중단 경계 |

각 검사는 다른 오류를 다룬다. 쓰기 범위만 올바르게 해도 잘못된 분기 구현이 남을 수 있고, 명령을 제한해도 무한 반복은 가능하다. 학습 모형의 방어 전환을 실제 상용 게임 취약점 재현이나 현대 시스템 보안 보증으로 읽지 않는다.

## Triforce%의 역사적 주장

제작팀 FAQ는 SGDQ 행사에서 개조하지 않은 미국판 《Ocarina of Time》 1.0 카트리지와 컨트롤러 입력을 통한 라이브 데이터 주입을 사용했다고 설명한다. 원래 카트리지에 남은 자료, 당시 공개 자료를 바탕으로 재제작한 장면, 팀의 창작 내용을 구분한다. 따라서 새 장면이 보인다는 사실을 숨겨진 원본 콘텐츠 발견으로만 해석하면 틀린다. [제작팀 FAQ](https://gettriforce.link/faq.html)

개조하지 않은 카트리지라는 말은 외부 입력 장치나 호스트 컴퓨터를 사용하지 않았다는 뜻이 아니다. FAQ는 행사 N64에 RGB 영상 출력 개조가 있었으며 게임 내용에는 영향을 주지 않았다고 구분한다. 개발용 수정 ROM의 존재와 실제 행사 실행도 구분한다.

## 게임 실험에서 조절할 범위

컨트롤러 입력값, 값을 기록할 메모리 칸, 다음 실행 위치를 나누어 조절한다. 점수 데이터만 바꿀 때와 실행 위치까지 데이터 영역으로 옮길 때 게임 화면이 어떻게 달라지는지 비교하고, 쓰기 범위와 분기 대상 검사를 각각 켜서 어떤 경계가 동작을 막는지 보여준다. 허용 명령과 실행량 제한은 이 교육 모형이 멈추지 않도록 정하는 규칙이며 원작 게임에 적용된 패치라고 설명하지 않는다.

실제 Triforce%의 메모리 주소·입력열·실기기 동작은 이 모형으로 검증되지 않는다. 남길 핵심은 고전 게임의 입력이 데이터가 되는 과정과 그 데이터가 실행 대상으로 바뀌는 조건이다. 원래 카트리지의 콘텐츠와 팀이 주입한 새 장면도 화면 설명에서 구분한다.
