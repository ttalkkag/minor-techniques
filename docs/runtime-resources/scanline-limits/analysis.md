# 한 줄에 몰린 스프라이트의 누락과 깜박임

[그룹 요약](../README.md) · [출처와 판단](research.md)

전체 객체 수가 허용 범위 안에 있어도 같은 높이에 몰린 객체 일부가 사라질 수 있다. 전체 화면의 저장 한도와 한 스캔라인에서 처리하는 한도는 다른 제약이기 때문이다. 이 문서는 고전 그래픽 영상의 사례에서 출발하지만, 아래 계산은 제한 개수를 직접 정한 교육 모델이다. NES의 사이클 단위 에뮬레이션 명세는 아니다.

## 전체 수와 줄별 후보 수

화면 줄 `y`와 겹치는 스프라이트를 모아 `C(y)`라고 하자. 한 줄의 처리 한도를 `L`로 정한 모델에서는 그 줄에서 많아야 `min(|C(y)|, L)`개의 후보가 선택된다.

```text
C(y) = { i | top_i ≤ y < top_i + height_i }
누락 후보 수(y) = max(0, |C(y)| - L)
```

전체 보관 한도가 64개, 줄별 한도가 8개인 모형에서 높이 8픽셀인 객체 9개를 모두 `top=40`에 놓으면 `y=40~47`인 줄마다 후보는 9개다. 우선순위 뒤의 한 개는 이 줄들에서 선택되지 않는다. 9번째 객체를 `top=48`로 옮기면 전체 객체 수는 그대로 9개지만 두 높이 구간의 최대 후보 수는 각각 8개와 1개가 된다.

영상도 NES의 총 64개와 줄별 8개를 별개의 제한으로 소개한다. 다만 외부 하드웨어 자료의 본문 재접근이 되지 않아, 그 수치를 원작 전체 조건에 대한 검증 완료 사양으로 채택하지 않았다. [수집 구간과 접근 이력](research.md)

## 선택 단계와 실제 보이는 픽셀을 구별한다

교육 모델의 후보 집합은 사각형 높이 범위로 정한다. 이것만으로 두 객체가 실제 불투명 픽셀에서 겹쳤다는 뜻은 아니다. 후보에서 탈락한 것, 앞 객체가 뒤 객체를 가린 것, 투명 픽셀 때문에 보이지 않는 것은 서로 다른 상태다. 무엇을 후보로 세는지 정하지 않고 화면에서 보이는 객체 수만 세면 한도를 오해할 수 있다.

또한 스프라이트 한 개와 게임 캐릭터 한 명을 같다고 보면 안 된다. 자체 예시에서 캐릭터를 작은 조각 4개로 구성했다면, 같은 줄을 가로지르는 조각 수만큼 한도를 쓴다. 큰 보스 한 명과 작은 적 여러 명의 화면 결과를 비교하려면 조각 단위와 캐릭터 단위를 따로 표시해야 한다. 원작 게임의 정확한 조각 구성을 이 예시로 추정하지 않는다.

## 순환 우선순위는 누락을 분배한다

9개 객체의 위치와 줄별 후보 집합이 유지된다고 가정하자. 고정 순서에서 9개의 동일한 객체 중 앞 8개만 선택하면 마지막 하나가 계속 사라진다. 프레임마다 목록의 시작 지점을 하나씩 옮기면 9프레임 동안 각 객체는 8프레임 선택되고 1프레임 빠진다. 모든 객체의 장기 표시 비율은 `8/9`가 되지만 어느 한 프레임에도 9개가 함께 선택되는 것은 아니다.

| 방법 | 해결하는 부분 | 남는 대가 |
| --- | --- | --- |
| 고정 우선순위 | 중요한 객체를 먼저 보장 | 뒤쪽 객체의 지속 누락 |
| 순환 우선순위 | 누락을 여러 객체에 분산 | 깜박임, 프레임마다 다른 부분 누락 |
| 객체를 위아래로 분산 | 줄별 후보 집중 완화 | 배치·게임 진행 규칙 변화 |
| 장식 조각 수를 줄임 | 같은 줄에서 소비하는 후보 감소 | 표현 단순화 |
| 한도를 제거한 현대 렌더링과 비교 | 해당 모형 제약 해제 | 다른 렌더링 비용까지 사라지는 것은 아님 |

순환 모델에서 중요한 플레이어 조각을 항상 앞에 둘 수도 있지만, 나머지 객체가 나눠 쓸 수 있는 슬롯은 더 적어진다. ‘공평하게 순환’과 ‘중요한 객체를 보호’는 서로 다른 목표다. 하드웨어가 자동으로 공평한 순서를 만들어 준다고 설명하지 않는다.

## 원리를 드러내는 관찰 방법

스캔라인을 하나 선택하고 그 줄의 후보 순서·선택된 번호·누락된 번호를 나란히 보여준다. 한 프레임을 고정하면 선택 제한이 보이고, 여러 프레임을 누적하면 순환에 따른 분배가 보인다. 객체를 위아래로 움직이면 총개수는 같아도 집중도가 달라지는 것을 확인할 수 있다.

비교에서 충돌 판정과 객체 수명은 그대로 두고 표시 선택만 바꿔야 한다. 화면에서 빠졌다고 게임 객체까지 제거하면 표시 한도와 게임 로직을 혼동한다. 실제 NES의 OAM 평가 시점, 우선순위 버그, 스프라이트 크기 모드, 매퍼·게임별 기법은 별도 명세를 확인해야 한다. 이번 문서에서는 콘솔 실행이나 깜박임 실측을 하지 않았다.
