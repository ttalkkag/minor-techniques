2026-09-22 후속 조사에서 다룬 Unity 자료는 Pixel Perfect 패키지 소개를 가리켰다. 2026-09-23부터 사용한 6000.0 컴포넌트 레퍼런스를 이번에도 직접 읽어 Transform 불변과 필터 적용 위치를 더 정확히 설명했다. 서로 다른 버전의 패키지 페이지를 하나의 ‘최신 Unity’ 사양으로 합치지 않는다.

원영상 설명의 [Dithering](https://pixelart.fandom.com/wiki/Dithering), [Jaggies](https://pixelart.fandom.com/wiki/Jaggies)는 제작자가 첨부한 참고 링크다. 이번에 본문을 재검증하지 않았으므로 별도의 확인 완료 출처로 올리지 않는다. 외부 작가의 직접 설명과 공식 엔진 문서가 담당하는 주장을 분리했다.

## 기존 노트의 확장과 보류

기존 분석은 실제 반 픽셀 이동과 색 기반 표현을 구분했다. 상세 문서에는 4픽셀→6픽셀 확대, 두 칸의 밝기 이동, `round(px)/p`의 자체 격자 모델을 추가했다. 특정 엔진·게임의 내부 수식이나 원본 프레임을 복제한 것은 아니다. 밝기 수열은 선형 스칼라의 자체 모델이며 감마 인코딩된 RGB 값을 그대로 평균하라는 규칙으로 사용하지 않는다.

원영상의 Metal Slug 사례는 설명 대상이라는 사실만 보존한다. 그 작품의 실제 제작자 자료·전체 스프라이트 시트·프레임 단위 변화는 이번에 조사하지 않아 ‘모든 움직임이 이 기법’이라는 결론을 내리지 않는다. 실제로 더 자연스럽거나 아름답다는 판단도 문서 확인으로 증명되지 않는다.

남은 질문은 기준 해상도와 실제 표시 격자의 관계, 원본·아틀라스·최종 화면의 필터 조합, 스냅에 따른 카메라 움직임의 선호, 디더링 패턴이 이동 중 어떻게 보이는가이다. 자작 그림으로 배율·필터·스냅을 독립 비교하고 픽셀 결과와 사용자 관찰을 나눠 기록해야 한다. 기존 조사에서 남긴 표시 비교와 필터 확인은 미실행 과제로 유지한다.
