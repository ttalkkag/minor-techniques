# 픽셀 아트의 색·윤곽과 화면 격자

[그룹 요약](../README.md) · [출처와 판단](research.md)

작은 그림의 한 픽셀은 눈에 띄는 형태 변화다. 그래서 그림을 만드는 단계에서는 색·윤곽·픽셀 배열을 조절하고, 보여 주는 단계에서는 확대율·필터·카메라 좌표를 조절한다. 두 단계의 결과가 비슷하게 보일 수 있어도 원인과 해결 위치는 다르다.

## 그림에 있는 계단과 표시 과정에서 생기는 계단

픽셀 격자에서 대각선은 작은 가로·세로 구간으로 표현된다. 의도한 기울기와 무관하게 한 구간이 길거나 짧으면 윤곽이 울퉁불퉁하게 느껴질 수 있다. 선이 만나는 지점에 픽셀이 몰리면 부분적으로 두꺼워지기도 한다. 원영상의 더블 픽셀·jaggies 설명은 이런 미술적 가이드다. 일부러 두꺼운 윤곽이나 불규칙한 질감을 쓰는 작품까지 잘못 그렸다고 판정하지 않는다.

원본 픽셀이 일정하게 배치됐어도 비정수 배율로 표시하면 각 원본 픽셀을 같은 정수 개수의 화면 픽셀에 대응시킬 수 없다. 자체 격자 예시에서 가로 4픽셀을 1.5배 확대하면 출력은 6픽셀이다. 원본 한 칸의 이상적인 너비는 1.5칸이지만 실제 화면 격자는 정수 칸이므로, 단순 점 샘플링에서는 칸 너비가 1개와 2개로 나뉠 수 있다. 2배 확대는 각각 정확히 2칸에 대응할 수 있다.

이는 색을 부드럽게 섞을지 여부와도 다르다. 점 필터는 원래 색을 고르지만 비정수 크기의 대응 불균일을 없애지는 않는다. 보간 필터는 경계를 부드럽게 만들 수 있지만 팔레트 밖의 중간색이나 흐려진 경계를 만들 수 있다. Unity 6.0 URP도 기준 해상도·스냅·최종 확대 필터를 별도 설정으로 다룬다. 이 컴포넌트의 `Filter Mode`는 `Crop Frame`에서 `Stretch Fill`을 선택했을 때 최종 화면 확대에 적용되며 원본 텍스처의 필터 설정과는 별개다. [Unity Pixel Perfect Camera 레퍼런스](https://docs.unity3d.com/kr/6000.0/Manual/urp/2d-pixelperfect-ref.html)

## 서브픽셀 애니메이션은 실제 좌표 이동과 다르다

그림 전체를 1픽셀 옮기면 변화가 너무 클 때, 윤곽과 내부 음영의 색을 프레임마다 바꿔 더 작은 움직임을 느끼게 할 수 있다. 픽셀 격자가 더 촘촘해진 것은 아니다. 픽셀 아티스트의 직접 예제는 경계와 명암의 변화를 이용한 움직임을 보여 준다. [2D Will Never Die의 직접 예제](https://2dwillneverdie.com/tutorial/give-your-sprites-depth-with-sub-pixel-animation/)

자체 도식에서는 두 인접 칸의 밝기를 `(1, 0) → (0.75, 0.25) → (0.5, 0.5) → (0.25, 0.75) → (0, 1)`처럼 바꾸어 색 분포 중심이 이동하는 과정을 볼 수 있다. 이 수열은 정규화한 선형 밝기의 설명 모델이며 감마 인코딩된 RGB 바이트를 그대로 평균하는 규칙은 아니다. 제한 팔레트에서는 모든 중간값을 표현할 수 없고, 실제 작화는 형태·재질·배경 대비에 맞게 색을 선택한다. 이 수열이 항상 자연스럽다는 미적 판단까지 포함하지 않는다.

여기서 다루는 공간 디더링은 다른 문제를 다룬다. 두 색을 공간 패턴으로 배치해 중간톤처럼 느끼게 한다. 저장 색 수를 늘리지 않아도 인상이 달라지지만, 확대해서 보면 두 색은 그대로다. 움직이는 화면에서 패턴이 번쩍이거나 배경에 섞여 읽기 어려울 가능성은 따로 관찰해야 한다.

## 좌표 스냅은 출력 위치를 양자화한다

한 월드 단위를 `p>0`픽셀로 대응시키고 카메라를 제외한 단순 1차원 모델을 생각하면, 출력 격자에 맞춘 위치는 `x_display=round(px)/p`로 나타낼 수 있다. 실제 좌표 `x`는 계속 부드럽게 움직여도 표시 좌표는 경계를 넘을 때 한 칸씩 바뀐다. 이 식은 효과를 설명하는 자체 모델이며 엔진의 내부 좌표 계산식을 그대로 옮긴 것은 아니다.

Unity Pixel Snapping은 렌더링 시 스프라이트를 격자에 맞추며 게임 오브젝트의 Transform 자체를 바꾸지 않는다. 따라서 표시 떨림을 줄이는 설정을 물리 좌표까지 정수화하는 작업으로 설명하면 안 된다. [Unity의 픽셀 스내핑 절](https://docs.unity3d.com/kr/6000.0/Manual/urp/2d-pixelperfect-ref.html)

| 증상 | 먼저 구별할 원인 | 대응 |
| --- | --- | --- |
| 정지 원본부터 윤곽이 불규칙함 | 의도한 미술 표현인지 배치 실수인지 | 원본 픽셀·선 흐름 검토 |
| 확대율에 따라 선 두께가 바뀜 | 원본/출력 격자 대응 | 기준 해상도·정수 배율·최종 필터 비교 |
| 카메라를 조금 움직이면 경계가 흔들림 | 표시 좌표의 격자 정렬 | 카메라와 스프라이트의 표시 스냅 정책 비교 |
| 한 픽셀 애니메이션이 너무 크게 느껴짐 | 원본 프레임의 표현 해상도 | 색 기반 서브픽셀 작화 비교 |
| 제한 팔레트에서 명암 단계가 거침 | 사용 가능한 색과 공간 패턴 | 색 선택·디더링을 배경 대비와 함께 검토 |

## 관찰 기준

같은 자작 그림을 원래 크기와 확대 격자로 함께 보여 주고, 원본 프레임·배율·필터·표시 스냅을 각각 바꾼다. 1·1.25·1.5·2배와 작은 카메라 이동을 분리해 비교해야 어떤 단계에서 픽셀이 달라졌는지 알 수 있다. 선명한 픽셀을 유지하는 조건과 부드러운 움직임을 선호하는 조건은 같지 않을 수 있다.

이번 문서에서 원작 그림 재배포, 전체 애니메이션 프레임 분석, 브라우저 최종 픽셀 검사나 사용자 미적 평가는 수행하지 않았다.
