## 원자료의 내용

[애니메이션 수학 영상](https://www.youtube.com/shorts/TomzUe30Ltg)의 기존 분석 위치는 00:18 선형, 00:24 smoothstep, 00:27 smootherstep, 00:42 cubic 그래프다. 수집 ID는 `animation-curves`다. 2026-09-25 기존 자막·대표 화면 분석을 재검토했으며 이번 전체 영상 재생·브라우저 애니메이션 비교는 미실행이다.

## 정의와 계산을 분리한 근거

[W3C CSS Easing Functions Level 1](https://www.w3.org/TR/css-easing-1/)의 2.2와 2.2.1을 09-25 열람했다. 제어점 x의 범위, x가 입력이고 y가 출력이라는 정의를 확인했다. 이것이 곡선 매개변수 u와 시간 t를 구분하고 x를 역산하는 이유다. 명세가 브라우저 지원 범위나 특정 계산법의 속도 우위를 입증하는 것은 아니다.

smoothstep·smootherstep의 끝점 값·도함수와 T에 따른 스케일은 제시한 다항식을 직접 미분한 결과다. 베지에 역산 예시는 비교를 위한 자체 수치 계산이다. 원영상에 그 수치나 예제가 등장했다고 표시하지 않는다.

2026-09-26 같은 명세의 범위 밖 입력 규칙을 다시 확인했다. cubic-bezier의 접선 연장과 이 문서의 clamp 후 정지를 구분하도록 분석을 보완했다. `cubic-bezier(1,0,0,0)`의 중앙 특이점은 허용 제어점 범위 안에 있는 자체 미분 반례이며, 명세가 유한한 속도를 보장한다고 해석하지 않는다.

[Ken Perlin의 Improved Noise 참조 구현](https://mrl.cs.nyu.edu/~perlin/noise/)도 09-26 열어 `fade(t)=t³(t(6t−15)+10)`를 대조했다. 분석의 smootherstep과 같은 다항식이다. 끝점 도함수 성질은 직접 미분으로 확인하며, 노이즈용 코드가 모든 애니메이션에 이 곡선을 권장하는 근거는 아니다.

## 기존 조사에서 유지·보류한 내용

09-22 조사에서는 CSS Easing 2의 `linear()`를 구간별 근사 후보로 소개했다. 이번 문서는 이를 필수 구현이나 최신 지원 완료 기능으로 승격하지 않는다. 실제 대상 브라우저를 결정한 뒤 지원 범위와 근사 오차를 확인하면 된다.

이징의 자연스러움은 목적에 달려 있다. 끝에서 멈출 필요가 없는 이동에 정지형 곡선을 적용하는 것이 항상 개선은 아니다. 베지에가 다항식보다 빠르다거나 모든 애니메이션 시스템이 베지에로 대체한다는 주장은 확보한 자료로 뒷받침되지 않는다.

## 남은 질문

실제 실행 시 재시작·역재생의 값 연속성, 단일 cubic으로 근사한 bounce의 최대 오차, 시간 간격 변화에서 렌더링된 궤적은 아직 확인하지 않았다. 곡선 수학의 검산과 브라우저의 애니메이션 실행을 구분해 후속 작업으로 남긴다.
