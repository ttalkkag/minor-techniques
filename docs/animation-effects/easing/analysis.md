# 이징: 위치가 이어져도 움직임이 튀는 이유

[분류 요약](../README.md) · [근거와 조사](research.md)

## 원인과 시간 단위

시작점과 끝점이 같아도 연결점에서 속도가 급변하면 움직임이 끊겨 보일 수 있다. 위치 곡선의 기울기는 속도, 기울기의 변화는 가속도다. 곡선 그림만 비교하면 실제 재생 시간에 따른 차이를 놓치기 쉽다.

시작점 p0, 끝점 p1, 지속 시간 T>0을 정하고 정규화 시간 `t=clamp(경과 시간/T,0,1)`을 쓴다. 위치는 `p=p0+(p1−p0)f(t)`다. 이동 구간 내부 `0<경과 시간<T`에서 f가 해당 차수까지 미분 가능하다면 실제 속도는 `(p1−p0)f′(t)/T`, 가속도는 `(p1−p0)f″(t)/T²`다. 같은 진행률에서 곡선의 시간을 절반으로 줄이면 속도는 2배, 가속도는 4배가 된다. 구간 밖에서는 위치를 고정하므로 속도·가속도가 0이고, 경계에서 도함수가 이어지는지는 별도로 확인해야 한다. 이는 수식의 직접 계산이며 브라우저 실행 측정값은 아니다.

## 어떤 연결을 원하는지 선택한다

| 함수 | 진행률 f(t) | 양 끝에서의 성질 | 적절한 목적 |
|---|---|---|---|
| linear | t | 속도가 일정함 | 일정 속도 이동, 기계적 진행 |
| smoothstep | 3t²−2t³ | 속도 0 | 멈춰 있던 물체가 이동 후 멈춤 |
| smootherstep | 6t⁵−15t⁴+10t³ | 속도·가속도 0 | 정지 구간과 더 부드럽게 연결 |

smoothstep의 도함수는 `6t−6t²`, 이차 도함수는 `6−12t`다. 양 끝에서 속도는 0이지만 가속도는 ±6이다. 정지 구간의 가속도 0과 이어 붙이면 가속도 변화가 남는다. smootherstep은 양 끝에서 이차 도함수도 0이다. 그렇다고 모든 구간에서 이 곡선이 좋은 것은 아니다. 계속 달리는 캐릭터가 매 구간 끝에서 멈추는 것은 의도와 어긋난다.

## CSS 베지에의 시간은 곡선 매개변수와 다르다

`cubic-bezier(x1,y1,x2,y2)`는 2D 곡선의 x가 입력 진행률이고 y가 출력 진행률이다. x1·x2는 [0,1] 안이어야 하지만 y1·y2에는 같은 범위 제한이 없다. 곡선 매개변수를 u라 하면 `x(u)=t`를 만족하는 u를 찾은 다음 `y(u)`를 구해야 한다. `y(t)`로 바로 계산하면 일반적으로 CSS와 다른 결과다. [W3C CSS Easing 1, 2.2·2.2.1](https://www.w3.org/TR/css-easing-1/)

앞의 시간 clamp와 구간 밖 정지는 이 문서의 이동 정책이다. CSS 이징 함수 자체는 범위 밖 입력도 정의하며, cubic-bezier는 가까운 끝점 쪽 제어점으로 정한 접선으로 연장한다. 제어점 배치에 따른 예외도 있으므로 CSS를 재현할 때 무조건 [0,1]로 자르면 명세와 달라질 수 있다.

자체 예로 x 제어점을 0과 1로, y 제어점을 0과 0으로 두면 `x(u)=3u²−2u³`, `y(u)=u³`다. 입력 t=0.25에서 u는 약 0.32635, 출력은 약 0.03476이다. u=t로 잘못 대입한 0.015625와 다르다. 단순한 그래프에서도 역산 단계가 필요한 이유다.

유효한 제어점이라고 모든 입력에서 유한한 속도가 존재하는 것은 아니다. 예를 들어 `cubic-bezier(1,0,0,0)`은 `x(u)=0.5+4(u−0.5)³`, `y(u)=u³`이다. 입력 t=0.5에서는 u=0.5, 출력은 0.125로 정의되지만 `x′=0`, `y′=0.75`이므로 `dy/dt=y′/x′`에 유한한 값이 없다. 정확한 특이점과 바로 옆의 큰 유한 미분값을 구분해야 한다. 이는 명세가 허용하는 제어점을 직접 미분한 자체 경계 예다.

## 해결 절차와 대가

먼저 시작·끝에 정지할지, 다른 구간의 속도를 유지할지 정한다. 이후 지속 시간과 곡선을 함께 고르고 위치·속도·가속도를 같은 시간축으로 표시한다. CSS와 비교할 때는 x 역산 오차를 따로 본다. 역재생·중간 재시작에서는 현재 위치에서 새 곡선을 시작하는지 이전 시간축을 뒤집는지도 결정한다.

bounce·overshoot는 방향 반전이나 범위 밖 출력을 의도할 수 있다. 시각적인 튕김을 체력 값·완료율·충돌 위치에 그대로 적용하면 음수나 중복 이벤트가 생길 수 있어 값의 의미에 맞는 정책이 필요하다. 단일 베지에가 모든 bounce를 정확히 표현하거나 다항식보다 항상 빠른 것은 아니다. 2D 곡선과 움직이는 점만으로 충분히 설명할 수 있는 주제다.
