# Mode 7과 평면 투영 리서치

[상세 분석](analysis.md) · [그룹 요약](../README.md)

## 자료의 출처와 열람 시점

수집 ID는 `mode7-graphics`, 원영상은 [3D처럼 눈속임하는 고전 게임의 비밀](https://www.youtube.com/shorts/R06WXFSWYvo)이다. 영상 길이는 41초, 게시일은 2025-09-11이다.

영상 근거는 2026-09-22의 자막·대표 화면 분석이다. 2026-09-25에는 그 분석과 전체 자막·시간별 OCR 텍스트, 공개 구현 소스, 공식 인터뷰를 대조했다. 전체 영상을 새로 재생하거나 프레임을 새로 수동 검토한 것은 아니다. 아래 표는 해석과 해당 영상 시점을 연결하며, 하드웨어에 관한 판단은 공개 구현과 개발자 회고에 근거한다.

## 영상 주장과 근거의 연결

| 시각과 자료 | 영상의 주장 | 판단과 보완 |
| --- | --- | --- |
| 00:02~00:04, 자막 / 00:03 OCR | 코스 이미지를 타일맵으로 표현 | 자막의 “타임맵”은 화면 OCR의 `2D 타일맵`과 구별해 읽음 |
| [00:15 원영상](https://www.youtube.com/watch?v=R06WXFSWYvo&t=15s), 기울이기 변환식 | 이동·확대·회전·기울이기를 설명 | 자막의 “앞 변환”은 신뢰할 기술 명칭으로 채택하지 않음. 전역 아핀 변환이라는 기존 해석을 유지 |
| [00:27 원영상](https://www.youtube.com/watch?v=R06WXFSWYvo&t=27s), 00:26~00:31 자막 | 화면을 줄 단위로 그리는 설명 | 자동 자막의 브라운관 관련 오인식은 원문 그대로 기술 정의에 사용하지 않음 |
| [00:33 원영상](https://www.youtube.com/watch?v=R06WXFSWYvo&t=33s), 00:31~00:36 자막 | 행마다 다르게 확대해 도로를 보이게 함 | 하나의 전역 변환과 구별 |
| 00:38~00:40 자막 / 00:39 OCR | 코스가 평평하다는 설명 | 모든 게임의 입체 표현이 불가능하다는 하드웨어 일반론으로 확대하지 않음 |

이 표는 자막·OCR 텍스트와 기존 대표 화면 분석에 근거한다. 부정확한 자동 인식 문장을 정밀한 하드웨어 사양으로 취급하지 않았다.

| 출처와 정확한 위치 | 뒷받침하는 내용 | 채택 범위 |
| --- | --- | --- |
| [bsnes `ppu-fast/mode7.cpp`](https://github.com/bsnes-emu/bsnes/blob/master/bsnes/sfc/ppu-fast/mode7.cpp), `PPU::Line::renderMode7`, `y`, `a/b/c/d`, `originX/Y`, `pixelX/Y`, 타일 읽기 부분 | 행 좌표와 계수로 맵의 읽을 위치를 계산하는 실제 공개 구현 | 에뮬레이터 근거. 닌텐도 게임 원본 코드가 아님 |
| [bsnes `ppu-fast/line.cpp`](https://github.com/bsnes-emu/bsnes/blob/master/bsnes/sfc/ppu-fast/line.cpp), `PPU::Line::cache`, `vcounter`와 IO 복사 | 행별 상태 보관 | 한 프레임 전체가 반드시 같은 변환 상태라는 가정 배제 |
| [닌텐도 공식 인터뷰](https://www.nintendo.com/jp/topics/article/3228ce3a-8d29-11e7-8cda-063b7ac45a6d), 2017-09-21, `「２人用の『F-ZERO』をつくろう」` 절, 곤노·스기야마 답변 | 2인 화면·긴 직선 표시 제약에서 코스 형태와 카트 선택으로 이어진 설계 맥락 | 직접 회고로 채택. 모든 코스의 평탄성이나 HDMA 데이터를 확인한 근거가 아님 |
| [Godot Camera3D](https://docs.godotengine.org/en/stable/classes/class_camera3d.html#enum-camera3d-projectiontype), `ProjectionType`의 perspective / orthogonal | 원근·직교 투영의 차이 | 현재 비교 구현의 개념 참고. 역사적 성능 비교의 근거로 쓰지 않음 |

bsnes 링크는 열람 당시 `master`의 지정 함수이며 불변 커밋을 고정한 검증 기록은 아니다. 이번에는 소스를 읽었고 에뮬레이터를 빌드·실행하지 않았다.

## 투영 원리와 자체 모델

한 번의 아핀 변환은 원근 투영이 아니다. 행별 바닥 투영은 같은 행 안에서 일정한 증가량을 사용하지만 행 사이에서는 그 증가량이 달라진다. 상세 분석의 핀홀 식은 이 관계의 조건과 도출, 수치 예제를 제공한다.

`H=2, F=200`에서 두 행이 읽는 거리는 자체 설명용 계산이다. 실제 Super Mario Kart의 카메라 상수나 SNES 레지스터 값을 가져온 것이 아니다. 원영상·공식 회고·에뮬레이터·자체 수학 모델이 서로 다른 주장을 뒷받침하도록 나눴다.
