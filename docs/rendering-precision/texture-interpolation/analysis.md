# 비스듬한 바닥의 무늬가 휘는 이유

[그룹 요약](../README.md) · [출처와 조사 기록](research.md)

## 문제가 생기는 단계

체크무늬 바닥을 비스듬히 보면 가까운 부분은 크게, 먼 부분은 작게 보인다. 정점의 화면 위치가 맞더라도 그 사이에 어떤 텍스처 좌표를 넣는지가 틀리면 무늬가 휜다. 카메라를 멈췄는데도 남아 있는 무늬의 뒤틀림을 먼저 관찰하면, 이동 중 윤곽이 뛰는 [화면 정점 양자화](../screen-coordinate-precision/analysis.md)와 구별하기 쉽다.

처리 순서는 `3D 정점과 UV → 정점 투영 → 화면 안쪽의 UV 보간 → 텍스처 읽기`다. 아핀 보간의 문제는 세 번째 단계에 있다. Sony 당시 문서는 PlayStation의 아핀 텍스처 매핑과 면 분할을 통한 우회를 설명한다. 이는 하드웨어의 역사적 사례이며 특정 게임의 실제 실행을 다시 측정한 결과는 아니다. [Sony, Run-Time Library Overview, 8-33~8-35쪽](https://psx.arthus.net/sdk/Psy-Q/DOCS/LibOver47.pdf#page=115)

## 화면의 중간과 원래 면의 중간이 다른 이유

클리핑을 마친, 넓이가 0이 아닌 화면 삼각형 안 한 점의 무게를 `λ₀, λ₁, λ₂`라 하자. 각 무게는 0 이상이고 합은 1이다. 정점별 UV의 한 성분을 `qᵢ`, 원근 나눗셈 전 clip 좌표의 w 성분을 `wᵢ`라 두면 비교식은 다음과 같다. 여기서는 가시 영역의 정점들이 `wᵢ>0`인 관례를 사용한다.

```text
아핀 보간       q = Σ(λᵢ × qᵢ)
원근 보정 보간  q = Σ(λᵢ × qᵢ / wᵢ) / Σ(λᵢ / wᵢ)
```

다음은 위 식에 직접 값을 넣은 설명용 예다. 삼각형의 한 변에서 가까운 끝은 `q=0, w=1`, 먼 끝은 `q=1, w=4`이고 화면상 가운데를 선택한다. 두 끝의 화면 무게는 각각 0.5다.

| 계산 | 결과 |
| --- | --- |
| `0.5 × 0 + 0.5 × 1` | 아핀 UV는 `0.5` |
| `(0.5 × 0 / 1 + 0.5 × 1 / 4) / (0.5 / 1 + 0.5 / 4)` | 원근 보정 UV는 `0.2` |

즉 화면의 가운데에서 텍스처의 가운데를 읽는 것이 항상 맞지는 않다. 반대로 모든 정점의 `w`가 같으면 분모가 공통값으로 정리되어 두 식은 같아진다. 면의 깊이 차이가 거의 없을 때 왜곡이 덜 보이는 이유도 이 비교로 설명할 수 있다. 수치 예제는 2026-09-25에 JavaScript 계산으로 확인했다.

## 해결 방법을 선택하는 기준

**원근 보정 보간**은 현재 렌더러에서 올바른 투영 결과를 얻으려는 경우의 직접적인 해법이다. 선택 픽셀까지 `q/w`와 `1/w`를 보간한 뒤 나누는 과정을 설명하면 된다. 화면이 맞게 보이는지와 역사적 하드웨어를 재현했는지는 별개의 목표다.

**3D 면 분할**은 아핀 보간을 유지한 채 각 작은 면 안의 근사 오차를 줄이는 방법이다. 원래 면 위에 새 정점을 만들고 그 위치와 UV를 구한 다음, 새 정점도 다시 원근 투영한다. 이미 화면에 투영된 삼각형을 기존 아핀 UV 그대로 잘게 나누면 원래 선형 함수를 세분할 뿐이므로 왜곡이 줄지 않는다. 분할점의 좌표를 어느 공간에서 계산했는지가 핵심이다.

**텍스처 해상도 증가**는 이미지의 세부 묘사를 늘리는 변경이다. 같은 잘못된 UV를 더 선명한 이미지에 적용하므로 보간 문제의 해결책으로 선택하지 않는다.

분할 수가 많아지면 제출 정점·면이 늘어난다. 다만 당시 Sony 문서는 텍스처 캐시와 클리핑 측면의 이점도 함께 다룬다. 삼각형 수 하나만으로 전체 실행 시간이 반드시 늘거나 줄었다고 판단할 수는 없다. [Sony, Primitive Division, 8-34~8-35쪽](https://psx.arthus.net/sdk/Psy-Q/DOCS/LibOver47.pdf#page=116)

## 원인을 분리해서 보여주는 구성

동일한 바닥·무늬·카메라를 사용하고 처음에는 화면 정점 양자화를 끈다. 보간만 바꿨을 때의 무늬 차이를 보여준 뒤, 아핀 모드에서 분할 수를 늘린다. 바닥 면을 화면 평면과 평행하게 돌려 모든 정점의 시선축 깊이가 같아진 조건을 대조군으로 넣으면 깊이 차이의 역할이 드러난다.

선택한 픽셀의 UV와 기준 UV 차이, 제출 삼각형 수를 관찰값으로 삼는다. 이미지 오차는 필터링·화면 해상도의 영향도 받으므로 UV 오차와 분리한다. 정점 양자화를 추가로 켰을 때 윤곽은 계속 뛸 수 있다. 색 정밀도·디더링·깊이 정렬까지 하나의 스위치로 섞으면 어떤 단계의 개선인지 설명하기 어려워진다.
