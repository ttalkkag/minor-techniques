# 작은 이동이 화면에서 한 칸씩 뛰는 이유

[그룹 요약](../README.md) · [출처와 조사 기록](research.md)

## 윤곽을 먼저 관찰한다

단색 삼각형을 화면에서 천천히 이동시켜 보자. 이상적인 모서리 위치는 연속적으로 바뀌어도, 투영된 좌표의 소수 부분을 없애면 여러 위치가 같은 화면 좌표가 된다. 값이 다음 경계를 넘는 순간 모서리가 한 칸 뛰어 보인다. 무늬를 지워도 남는 현상이므로 텍스처 UV 보간과 분리할 수 있다.

Sony의 GTE 명세는 화면 좌표 레지스터 SXY0의 X·Y를 `(1.15.0)`으로 정의한다. 이는 부호 1비트·정수부 15비트·소수부 0비트라는 표기다. 이 형식이 화면 좌표 단계의 정밀도 제한을 뒷받침한다. [Sony, Inline Programming Reference, 5-34쪽](https://psx.arthus.net/sdk/Psy-Q/DOCS/Devrefs/Inlinref.pdf#page=118), [수 형식 정의 6-4쪽](https://psx.arthus.net/sdk/Psy-Q/DOCS/Devrefs/Inlinref.pdf#page=134)

## 어느 단계에서 정보를 잃는가

```text
모델 위치 → 카메라 좌표 → 투영한 연속 화면 위치 s → 양자화 Q(s) → 픽셀 채우기
```

아래는 설명을 위해 양자화 규칙을 `Q(s)=g × floor(s/g)`로 정한 예다. `g`는 화면 격자 간격이며, 이 규칙이 GTE의 모든 명령·반올림·포화 동작을 재현한다는 뜻은 아니다.

| 연속 위치 s | 격자 g=1의 출력 | 잃는 차이 |
| --- | --- | --- |
| 10.1 | 10 | 0.1 |
| 10.4 | 10 | 0.4 |
| 10.9 | 10 | 0.9 |
| 11.1 | 11 | 0.1 |

처음 세 시각에서는 내부 위치가 움직여도 같은 좌표가 출력된다. 네 번째에서 한꺼번에 바뀐다. 일반 화면 해상도가 유한한 것과, 정점 좌표를 래스터화 전에 강제로 격자에 붙이는 것은 구별해야 한다. 전자는 마지막 픽셀 출력의 문제이고 이 예는 그 이전 정점 위치에서 정보를 버린다.

## 해결과 한계

현재 렌더러의 정확도를 개선하려면 화면 정점의 소수 부분을 불필요하게 버리지 않아야 한다. 반면 역사적 화면 느낌을 설명하려면 의도적인 양자화를 독립 스위치로 둔다. 스위치가 켜졌을 때 값이 어느 격자로 바뀌는지를 보여주면 원인을 읽을 수 있다.

원근 보정 보간은 면 안의 무늬를 바꾼다. 이미 반올림한 모서리의 위치는 되살리지 않는다. 면 분할도 새 정점들을 추가할 뿐이므로, 각 정점을 같은 격자로 양자화하면 정점의 이동 제한이 남는다. 카메라 이동을 더 부드럽게 보간하더라도 최종 양자화 규칙을 통과하는 값이 같다면 작은 이동은 계속 사라진다.

좌표를 실제 화면 픽셀 기준으로 양자화할지, 별도 저해상도 기준으로 양자화한 후 확대할지 먼저 정해야 한다. 두 방식의 `1칸`이 다르므로 화면 크기 변경 때 격자도 함께 달라졌다면 같은 조건의 비교가 아니다.

## 설명에 필요한 관찰값

연속 정점과 양자화된 정점을 동시에 표시하고 차이를 선으로 연결한다. 일정한 속도로 이동하며 `s`, `Q(s)`, 두 값의 차이를 기록한다. 텍스처를 껐을 때도 같은 궤적 차이가 나야 한다. 보간 모드를 바꿔도 정점 위치는 바뀌지 않아야 한다.

음수 좌표에서는 내림과 0 방향 절삭이 다르다. 화면 경계, 오버플로, 포화 규칙까지 콘솔과 똑같이 맞추려면 명령별 추가 근거가 필요하다. 지금 문서가 정한 임의 규칙은 현상을 설명하는 수학 모델이며 실기 에뮬레이션이 아니다. PS1 화면의 색 정밀도·디더링·면 정렬 등도 이 한 가지 원인으로 설명하지 않는다.
