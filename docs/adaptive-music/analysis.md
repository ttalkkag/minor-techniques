# 이벤트 시각과 음악 전환 시각 맞추기

[주제 요약](README.md) · [리서치](research.md)

## 왜 동시에 켰는데 다르게 들릴 수 있나

게임은 프레임마다 상태를 갱신하지만 오디오는 별도 버퍼와 재생 시계를 사용한다. 전투가 시작된 프레임에 여러 Play 명령을 보냈다고 원하는 박자에 정확히 시작한다는 보장은 없다. 명령 전달 시점과 처리 버퍼 경계가 추가되기 때문이다. [Epic Quartz 개요](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-quartz-in-unreal-engine)

더 큰 문제는 음악 구조다. 탐험 루프의 세 번째 박에서 전투 루프의 첫 박을 시작하면 전환 시각이 정확하더라도 리듬과 화성이 어긋날 수 있다. 시간 예약과 작곡의 연결 조건은 각각 해결해야 한다.

## 악기를 더할지 구간을 바꿀지

| 구성 | 바꾸는 것 | 성립 조건 |
|---|---|---|
| 수직 레이어링 | 같은 곡 위치의 악기 층·볼륨 | 스템 길이·박자·시작 오프셋이 공통 시간축과 맞음 |
| 수평 전환 | 다음에 재생할 구간 | 앞 구간의 종료와 뒤 구간의 진입이 연결 가능 |
| 브리지 | 두 구간 사이 짧은 음악 | 언제 진입·탈출할 수 있는지 정해져 있음 |
| 짧은 반응음 | 게임 이벤트에 즉시 가까운 반응 | 본 음악의 전환 대기를 보완하되 믹스를 가리지 않음 |

레이어링의 동기화는 악기들의 음파 위상을 모두 똑같이 만든다는 뜻이 아니다. 같은 박자와 의도한 음악 위치에 맞추는 것이다. 이미 조용히 재생 중인 스템의 볼륨을 올리거나 현재 곡 위치에 맞춰 새로 시작하는 방식이 가능하다. 전자는 계속 재생하는 비용, 후자는 시작 오프셋 관리가 필요하다.

## 고정 템포의 전환을 계산하기

공통 시작 시각 t0, 양수 BPM, 한 마디의 박 수 b를 정하면 한 박 길이는 60/BPM초, 마디 길이 T는 b×60/BPM초다. b는 BPM이 세는 박 단위와 맞춰야 한다. 예약 여유 L≥0, 현재 오디오 시각 t≥t0에 대해 t+L 이상인 첫 허용 마디 경계는 다음과 같이 정할 수 있다.

```text
t_next = t0 + ceil((t + L - t0) / T) × T
```

이는 고정 템포 교육용 규칙이다. 120 BPM·4박자면 T=2초다. t0=0, t=3.90초, L=0.15초라면 t+L=4.05초이므로 4초 경계를 놓치고 6초에 예약한다. 반면 t=3.80초면 4초에 예약할 수 있다. 마디 직전 버튼을 눌러도 필요한 준비 시간을 확보하지 못하면 다음 마디까지 기다리는 이유다.

Web Audio에서는 화면 타이머의 실행 시각이 아닌 `currentTime` 시간축으로 재생을 예약한다. 이는 오디오 그래프의 처리 시각이며 스피커에서 이미 들린 시각과 같지는 않다. [Web Audio 1.0 시간 모델](https://www.w3.org/TR/webaudio-1.0/#dom-baseaudiocontext-currenttime) 예약 여유가 부족한 상황을 계산해서 보여 주는 위 수식이 API의 자체 정책인 것은 아니다.

## 예약이 여러 개 생기면 생기는 문제

전투 진입을 예약한 뒤 전투가 끝났을 때 기존 예약을 방치하면 평화 상태에서 전투 음악으로 바뀐다. 각 전환에 목적 상태와 예약 ID를 부여하고 유지·교체·취소 조건을 정한다. 다음 순서는 실험용으로 충분하다.

1. 현재 게임 상태와 현재 재생 구간을 구분해 기록한다.
2. 상태가 바뀌면 음악 전환이 필요한지 판단한다.
3. 예약 중인 목표와 같으면 중복 예약을 만들지 않는다.
4. 다른 목표면 아직 실행되지 않은 예약을 취소하거나 새 경계로 교체한다.
5. 실행 경계에서 예약 상태와 실제 재생 상태를 갱신한다.

이미 Web Audio 소스에 `start(when)`을 보냈다면 앱의 예약 ID만 지워서는 취소되지 않는다. 시작 시각 이전에 도달하는 `stop(when)`으로 그 소스의 재생을 막을 수 있으며, 같은 소스에서 `start()`를 두 번 호출할 수 없으므로 새 예약에는 새 소스가 필요하다. [소스 시작·정지 규약](https://www.w3.org/TR/webaudio-1.0/#AudioScheduledSourceNode)

일시정지·재개, 템포 변경, 리소스 로드 실패는 별도 전환이다. BPM이 바뀌면 위 고정 T 식을 계속 쓰지 말고 변경된 음악 시간축을 적용해야 한다.

## 선택과 관찰

다음 마디까지 기다리면 음악 연결이 자연스러워질 여지가 있지만 즉각 반응은 늦어진다. 단순한 분위기 변화에는 볼륨 페이드만으로 충분할 수도 있다. 스케줄러가 곡의 화성이나 루프 이음새를 자동으로 해결하지는 않는다.

관찰안은 합성 악기 3개와 탐험/전투 버튼, 박자 커서, 이벤트·예약·실행 시각 표시다. 마디 직전·직후, 연타, 프레임 지연을 비교한다. 예약 시간이 맞는지와 사람이 자연스럽게 듣는지는 다른 확인 항목이다. 실제 원작 음악 청취나 샘플 차이 측정은 수행하지 않았다.
