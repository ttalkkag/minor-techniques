## 확인한 자료와 날짜

수집 ID는 `adaptive-music`이다. 2026-09-22 보완·09-23 통합 검토에 이어 09-25 영상의 관련 자동 자막과 Epic·W3C 본문을 다시 열람했다. 09-26에는 Epic·W3C 기술 자료를 새로 검색하고 본문을 대조했다. 이전 영상 검토는 캡처 24장을 수집하고 대표 화면을 대조한 범위다. 아래 공개 영상의 장면과 시간 예약 규약을 근거로 사용하며 원음 청취·전체 영상 재생은 하지 않았다.

## 공식 자료를 통해 보완한 설명

[Epic Quartz Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-quartz-in-unreal-engine)의 `Latency: The Problem Quartz Solves`와 예약 동작 설명을 09-26 재열람했다. 게임 스레드 명령 전달, 오디오 버퍼 소비, 미래 시각 예약이 분리된다. 샘플 단위 예약이 이미 지나간 게임 이벤트를 소급 실행하거나 출력 장치 지연을 제거하는 기능은 아니다.

[W3C Web Audio 1.0 권고안](https://www.w3.org/TR/webaudio-1.0/)의 `BaseAudioContext.currentTime`, `AudioScheduledSourceNode.start()`·`stop()`을 09-26 확인했다. `currentTime`은 처리 블록의 시간축이고, 이미 예약한 소스의 취소에는 시작 전 정지가 필요하며 소스의 `start()`는 한 번만 호출할 수 있다. 일반 `/TR/webaudio/` 주소는 당시 1.1 작업 초안을 가리켜 이 설명의 근거를 2021-06-17의 1.0 권고안으로 고정했다. 다음 마디 계산·연타 취소 정책·브리지 선택은 별도의 프로젝트 설계다.

기존 설명의 “동일 템포·위상”은 “공유 박자/샘플 시간축과 의도한 시작 오프셋”으로 교정했다. 음악이 동기화되었다는 말과 모든 악기의 음파 위상이 같다는 말은 다르다.

## 미채택 또는 미확인

09-22 기록의 Wwise 문서는 당시 본문 fetch가 제한돼 최신 API 근거에서 제외되어 있었다. 이번에도 그 자료를 읽었다고 표시하지 않았다. 영상 설명에 첨부된 악보·영상 링크는 원작의 엔진 코드에 대한 직접 증거가 아니다.

기존 `qualified` 판정을 유지한다. 전환 수식의 120 BPM·4박자·0.15초 여유는 직접 구성한 계산 사례다. 원작이나 브라우저에서 측정한 지연 수치가 아니다.

## 다음 연구 질문

템포 변경 시 음악 위치를 어떻게 유지할지, 로드가 늦은 스템을 건너뛸지 다음 경계에서 넣을지, 반복 구간의 음량·클리핑을 어떻게 관리할지 정해야 한다. 실제 청취 품질과 출력 지연은 구현 후 각각 확인해야 하며, 현재 문서는 그 결과를 주장하지 않는다.
