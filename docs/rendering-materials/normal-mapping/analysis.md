# 노멀맵의 방향, 기하, 조명 분리

[그룹 요약](../README.md) · [조사 근거](research.md)

노멀맵을 입힌 평면은 빛이 이동할 때 요철처럼 보이지만 옆으로 보면 여전히 평면이다. 조명에 쓰는 방향만 바뀌었기 때문이다. 법선·정점·충돌체를 분리하면 어디까지 근사할 수 있는지 명확해진다.

## 방향 데이터가 색으로 보이는 이유

압축되지 않은 기본 RGB 표현에서 `RGB=(n+1)/2`로 방향 성분을 0~1에 담고 `n=normalize(2RGB-1)`로 복원한다. 중립값 `(0.5,0.5,1)`은 `(0,0,1)`이다. 실제 엔진의 압축 포맷은 채널을 재배치하거나 일부 성분을 복원하므로 해당 디코더를 사용한다. [Unity 노멀맵 문서, Colors in a normal map](https://docs.unity3d.com/6000.1/Documentation/Manual/StandardShaderMaterialParameterNormalMap.html)

접선 공간 법선이면 세계 공간에서 정규직교하도록 구성한 접선 `T`, 종접선 `B`, 기본 법선 `N`으로 `n_world=normalize(T·nx+B·ny+N·nz)`를 만든다. 로컬 기저를 그대로 쓰면 결과도 로컬 방향이므로 세계 공간 광원과 바로 내적하지 않는다. 보간·스케일 변환 후에도 기저가 올바른지 확인해야 한다. 법선 이미지를 색상 텍스처처럼 감마 변환하면 방향 자체가 변한다.

자체 예에서 `RGB=(0.8,0.5,0.9)`는 `(0.6,0,0.8)`을 뜻한다. 광원 방향이 `(0,0,1)`이면 코사인 항은 0.8이고, 중립 법선은 1이다. 기하를 바꾸지 않아도 두 픽셀의 밝기가 달라지는 이유다. 모든 방향은 단위벡터라는 전제가 있다.

## 조명 모델과의 관계

`max(0,n·l)`은 빛을 받는 방향의 코사인 기하항이다. [PBRT §8.3](https://www.pbr-book.org/3ed-2018/Reflection_Models/Lambertian_Reflection)의 Lambert BRDF는 반사율/π이며 이 코사인과 입사 조명을 별도로 결합한다. 내적 값을 곧바로 회색으로 출력한 교육 모형을 완전한 물리 조명이라고 부르지 않는다.

노멀맵이 없는 평면도 점광원과의 거리·방향이 픽셀마다 달라 밝기가 달라질 수 있다. “2D의 모든 픽셀은 언제나 같은 빛을 받는다”는 보편 명제는 성립하지 않는다.

## 해결 절차와 자산 연결

1. 맵이 접선 공간인지, Y+인지 Y-인지와 모델의 접선 기저를 확인한다. 축의 불일치를 조명 강도 조절로 숨기지 않는다.
2. 방향 데이터로 샘플링하고 엔진의 정식 디코더를 사용한다.
3. 색 프레임·노멀 프레임·아틀라스 UV를 일치시킨다. 애니메이션의 다음 프레임에서 법선만 이전 상태면 요철이 미끄러진다.
4. 스프라이트 좌우 반전과 음수 스케일에서 방향 기저도 맞춘다. UV만 뒤집는 것과 방향을 반사하는 것은 같은 처리가 아니다.
5. 실제 돌출·외곽·접촉이 필요한 부분은 메시나 충돌 형상을 별도로 만든다.

Dead Cells의 제작자는 3D 애니메이션 프레임을 PNG와 노멀맵으로 내보내 툰 셰이더에 연결했다고 설명한다. 이는 자산 제작 흐름의 사례다. [Thomas Vasseur의 직접 제작기](https://www.gamedeveloper.com/production/art-design-deep-dive-using-a-3d-pipeline-for-2d-animation-in-i-dead-cells-i-)

## 실패 조건과 비용

Y 채널 반전, sRGB 오설정, 프레임 UV 불일치, 잘못된 기저를 각각 독립적으로 비교한다. 옆 시점에서는 실루엣과 충돌체를 함께 표시해 방향만 바뀐다는 사실을 드러낸다. 추가 텍스처·조명·렌더 패스 비용은 남으며 작은 굴곡을 메시로 만드는 방법보다 무조건 빠르다는 결론은 내리지 않는다. 원작 셰이더·현행 모든 자산·브라우저 GPU 시간은 미측정이다.
