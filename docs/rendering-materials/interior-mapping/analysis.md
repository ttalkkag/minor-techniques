# 창문 픽셀에서 가상 방의 교차점 구하기

[그룹 요약](../README.md) · [조사 근거](research.md)

건물마다 방 메시를 넣지 않고도 시점에 따라 바뀌는 내부를 보여 줄 수 있다. 창문 픽셀에서 시선을 방 안으로 연장해 가상의 벽을 찾으면 된다. 정면 사진과 달리 교차 위치가 바뀌어 시차가 생기지만, 실제 방의 충돌·이동 공간이 만들어지는 것은 아니다.

## 작동 과정과 수치 예

설명용 방을 로컬 좌표 `x,y∈[-1,1]`, `z∈[0,3]`에 두고 창문을 `z=0`으로 둔다. 창문 테두리를 제외한 점 `p`(`p_x,p_y∈(-1,1)`)에서 카메라 반대 방향, 방 내부를 향하는 `d`(`d_z>0`)로 `q(t)=p+t·d`를 만든다. 방향은 정규화하지 않아도 교차 순서를 비교할 수 있지만 `t`를 미터 거리라고 표시하려면 단위 방향이어야 한다.

각 축에서 진행 방향 쪽 경계 `b`까지 `t=(b-p축)/d축`을 구한다. 양의 유한 값 중 가장 작은 것이 처음 만나는 방의 면이다. 시작 창문 면의 `t=0`은 방 내부 후보에서 제외하고, 방향 성분이 0인 축은 건너뛴다. 선택한 면의 나머지 두 좌표를 0~1 UV로 옮겨 텍스처를 읽는다.

`p=(0,0,0)`, `d=(0.5,0,1)`이면 오른쪽 벽 후보는 `t=2`, 뒷벽은 `t=3`이다. 따라서 `(1,0,2)`에서 오른쪽 벽을 본다. 카메라를 바꾸어 `d=(0,0,1)`이 되면 `(0,0,3)`의 뒷벽을 본다. 이 자체 박스 예가 시차의 원리를 보여 준다.

## 해결 절차

1. 카메라와 창문 픽셀을 같은 건물 로컬 좌표로 옮긴다.
2. 해당 창문이 속한 방의 폭·높이·깊이와 내부 방향을 정한다.
3. 경계 교차 후보를 만들고 가장 앞선 면의 텍스처를 선택한다.
4. 외벽 마스크로 창문과 실제 벽을 구분한다. 창문 밖까지 내부가 그려지는 오류를 막는다.
5. 가구가 필요하면 별도 가상 평면의 교차와 알파 마스크를 비교한다. 가구가 반드시 뒷벽에 붙어 있어야 하는 것은 아니다.

[Joost van Dongen의 원논문 §2](https://www.proun-game.com/Oogst3D/CODING/InteriorMapping/InteriorMapping.pdf)는 가상 천장·벽 교차, 외벽과의 합성, furniture plane 확장을 설명한다. 위 단일 방 계산은 이를 이해하기 위한 자체 좌표 예이고 원논문의 반복 층 구현을 그대로 옮긴 코드는 아니다.

## 조건과 대가

| 조건 | 문제 | 대응 |
| --- | --- | --- |
| 창문을 지나 내부로 이동 | 외부 표면에서만 계산하던 근사가 깨짐 | 실제 방 기하로 전환하는 경계 설계 |
| 가구를 옆에서 관찰 | 평면 가구가 입체 가림을 충분히 표현하지 못함 | 필요한 가구만 기하화하거나 관찰 범위 제한 |
| 건물 모서리·곡면 | 가구 평면의 왜곡·이음새 | 창문 배치·형상·깊이 조정 |
| 거의 평행한 광선 | 작은 분모와 큰 교차 거리 | 유효 범위·영방향 처리 |
| 넓은 화면을 창문이 덮음 | 픽셀 계산 비용 증가 | 화면 점유율과 해상도를 포함한 비교 |

실제 방보다 드로콜이 적어도 항상 빠르지는 않다. 기하·자산 메모리와 픽셀 작업을 비교해야 한다. 동일 박스 방을 기준으로 카메라 각도·방 깊이·가구 위치를 바꾸면 어떤 정보가 생략됐는지 확인할 수 있다. Spider-Man의 모든 창문 구현과 현재 GPU에서의 성능은 미확인이다.
