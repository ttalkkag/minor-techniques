# 연막의 밀도, 렌더링, 공유 상태 분리

[그룹 요약](../README.md) · [조사 근거](research.md)

연막이 부피처럼 보인다는 사실은 실제 유체 방정식을 푼다는 뜻도, 모든 플레이어의 시야 판정이 일치한다는 뜻도 아니다. 공간 상태를 만드는 과정, 그 상태를 그리는 과정, 게임 규칙에 사용하는 과정을 나눠야 한다.

## 표현이 달라지는 과정

빌보드는 텍스처 평면을 시선에 맞춰 구성한다. 볼륨 렌더링은 공간 위치 `x`의 밀도 `ρ(x)`를 시선 경로에서 조회해 누적한다. 밀도장은 고정된 배열, 이동하는 절차 함수, 베이크된 프레임, 유체 솔버의 출력일 수 있다. 렌더링 방식만 보고 생성 방식을 확정할 수 없다.

자체 단순 흡수·발광 모델에서는 샘플 구간의 소멸 계수 `β≥0`와 길이 `Δs`로 `α=1-exp(-βΔs)`를 둔다. 앞에서 뒤로 누적할 때 초기 `T=1`, `C=0`에서 다음을 적용한다.

```text
C_next = C + T·α·c
T_next = T·(1-α)
최종 색 = C + T·배경색
```

`c`는 샘플의 설명용 색이다. 이 모델은 다중 산란·광원 그림자를 모두 계산하지 않는다. [GPU Gems Chapter 39](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-39-volume-rendering-techniques)는 정렬된 샘플의 색·불투명도 누적과 간격 변화의 보정을 설명한다.

균일한 `β=0.5/m`, 길이 2m이면 자체 모델의 투과율은 `exp(-1)≈0.368`이다. 같은 구간을 10개 또는 20개로 나눠도 구간 길이에 맞춰 알파를 계산하면 총 투과율은 같다. 반대로 매 샘플에 고정 알파 0.1을 쓰면 `0.9¹⁰≈0.349`, `0.9²⁰≈0.122`로 달라져 품질 옵션이 불투명도를 바꾸는 오류가 생긴다.

## 상호작용과 멀티플레이어 상태

총격 구멍은 지정된 공간의 밀도를 바꾸는 이벤트로 모델링할 수 있다. 두 카메라에서 같은 이벤트와 밀도장을 쓰더라도 광선 경로와 통과 길이에 따라 최종 픽셀이 달라질 수 있다. 공유해야 하는 월드 상태와 시점별 화면을 혼동하지 않는다.

경쟁 규칙에서 연막이 시야를 차단한다면 서버 판단과 화면 품질의 관계를 별도로 정해야 한다. 저품질에서만 표적이 더 드러나는지, 이벤트 순서·시간이 달라 구멍 상태가 어긋나는지 확인한다. 이 조건은 자체 설계 질문이며 CS2의 서버 구현 설명이 아니다.

## 해결 절차와 대가

1. 고정 밀도부터 시작해 렌더링과 상태 생성의 입력을 분리한다.
2. 같은 월드 상태를 두 시점에서 그리되 샘플 간격에 맞춘 누적을 사용한다.
3. 구멍·바람·확산 이벤트를 각각 추가하고 무엇이 밀도를 바꾸는지 표시한다.
4. 시각화 해상도·샘플 수와 게임의 차폐 규칙을 독립적으로 바꿔 차이를 관찰한다.

볼륨은 시점별 샘플과 저장량 비용이 있고, 실제 유체는 상태 갱신 비용도 든다. [Niagara Fluids](https://dev.epicgames.com/documentation/en-us/unreal-engine/niagara-fluids-in-unreal-engine)는 유체 효과와 무거운 결과의 flipbook 베이킹을 함께 소개한다. 작은 장식 효과와 상호작용하는 연막에 같은 해법을 강제하지 않는다. 실제 CS2 솔버·격자·통신과 브라우저 성능은 미확인이다.
