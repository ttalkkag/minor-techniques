# 반사에 필요한 정보가 어디에 있는가

[그룹 요약](../README.md) · [조사 근거](research.md)

카메라를 돌렸더니 거울 속 물체가 사라지는 문제는 반사 벡터가 틀려서만 생기지 않는다. 참조하는 화면·큐브맵·다른 시점에 그 물체의 정보가 없을 수 있다. 반사 방식은 정보를 얻는 범위부터 비교해야 한다.

## 세 방식의 작동 과정

**평면 반사:** 평면 위 점 `m`, 단위 법선 `n`, 카메라 위치 `c`에 대해 반사 위치는 `c′=c-2n[n·(c-m)]`이다. 방향도 같은 평면으로 반사하고 거울 반대쪽에 불필요한 형상이 그려지지 않도록 클리핑한다. 예를 들어 거울이 `z=0`, 카메라가 `(1,2,3)`이면 반사 카메라는 `(1,2,-3)`이다. 이 위치 예는 자체 기하 계산이다. 장면 오브젝트를 복제하지 않고도 반사 시점으로 다시 그릴 수 있다. [Epic Planar Reflection](https://dev.epicgames.com/documentation/en-us/unreal-engine/planar-reflections-in-unreal-engine)

반사 변환은 좌우 방향성을 뒤집으므로 일반 카메라의 앞·뒷면 컬링 상태를 그대로 쓰면 보일 면이 제거될 수 있다. 반사 패스의 컬링 방향을 맞추고 종료 후 원래 상태를 복구해야 한다. [Unity GL.invertCulling](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/GL-invertCulling.html)은 거울·물의 반사 카메라를 이 기능의 사용 사례로 명시한다. 위치만 반사했다고 완성된 반사 카메라가 되는 것은 아니다.

**큐브맵:** 한 지점에서 주변 여섯 방향으로 얻은 색을 반사 방향으로 조회한다. 입사 방향 `i`와 단위 법선 `n`의 반사 방향은 `r=i-2n(n·i)`이다. 방향별 색만 재사용하므로 관찰점이 이동해도 주변 벽과의 실제 거리가 자동 반영되지 않는다. Box Projection은 근사 상자와의 교차점을 이용해 캡처점의 조회 방향을 보정하지만 방의 모든 형상을 복원하지는 않는다. [Unity Box projection](https://docs.unity3d.com/6000.0/Documentation/Manual/AdvancedRefProbe.html)

**화면 공간 반사(SSR):** 현재 카메라의 깊이·색 정보를 이용해 반사 방향의 후보를 화면 공간에서 찾는다. 화면 밖으로 나가거나 주 카메라에서 다른 표면 뒤에 가려진 대상은 데이터에 없다. 샘플 수를 늘려도 없는 화면 밖 색이 생기지는 않는다.

## 요구에 따른 해결 절차

1. 화면 밖 동적 물체, 정적인 실내 분위기, 거친 작은 물체 중 무엇을 반사해야 하는지 정한다.
2. 평면 거울에는 반사 카메라 후보, 주변 색 재사용에는 큐브맵 후보, 화면 정보 활용에는 SSR 후보를 둔다.
3. 큐브맵 캡처 위치·갱신 시점, 반사 해상도, SSR 실패 시 보완 표현을 명시한다.
4. 같은 물체를 화면 밖·가림 뒤·캡처점에서 먼 곳으로 이동하며 정보의 공백을 확인한다.

| 방법 | 남는 오차 | 추가 비용 |
| --- | --- | --- |
| 평면 반사 | 곡면·거울 중첩·클리핑 설정 문제 | 추가 장면 제출·렌더 대상·해상도 |
| 큐브맵 | 시차·캡처 시각의 차이 | 저장량·재캡처·프로브 혼합 |
| SSR | 화면 밖·숨은 표면의 부재 | 깊이 추적·샘플·실패 구간 보완 |

## 혼합 방식과 판단 경계

[Epic Lumen의 Screen Tracing](https://dev.epicgames.com/documentation/unreal-engine/lumen-technical-details-in-unreal-engine)도 화면 추적과 다른 장면 표현을 함께 사용한다. 이런 구성이 있다는 사실은 최신 기술이 비용 없이 완전한 거울을 만든다는 뜻이 아니다. 위 세 방식도 반사 기술 전체 목록이 아니다.

평면 반사가 “요즘 쓰이지 않는다”는 사용 빈도 주장은 채택하지 않는다. 학습 화면에서는 반사에 쓰인 화면·캡처점·가상 카메라를 각각 드러내야 한다. 자유 관찰 카메라를 움직였다고 기준 카메라의 SSR 정보까지 바꾸면 같은 조건의 비교가 되지 않는다. 실제 GPU 비용·특정 게임의 내부 렌더러는 아직 확인하지 않았다.
