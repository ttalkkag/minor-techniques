# 색 합성과 알파 표현의 불일치

[그룹 요약](../README.md) · [조사 근거](research.md)

밝게 더한 효과가 흰 배경에서 사라지는 현상과 투명 경계가 검어지는 현상은 다르다. 전자는 배경과의 대비, 후자는 색·알파의 표현과 합성 과정부터 살펴야 한다.

## 합성에서 실제로 저장하는 값

straight 색 `C`는 알파를 곱하지 않은 RGB이고 premultiplied 색 `c=Cα`는 이미 알파가 포함된 값이다. 이 둘을 같은 값으로 취급하면 가장자리처럼 알파가 작은 곳에서 오차가 두드러진다.

전경 `Cs, αs`, 배경 `Cb, αb`를 source-over로 합치면 다음 관계가 성립한다. [W3C Compositing §5.1](https://www.w3.org/TR/compositing-1/#simplealphacompositing)

```text
αo = αs + αb(1-αs)
co = Csαs + Cbαb(1-αs)
Co = co / αo                  // αo > 0일 때만
```

자체 예로 빨강 `Cs=(1,0,0), αs=0.4`를 파랑 `Cb=(0,0,1), αb=0.25` 위에 놓으면 `αo=0.55`, `co=(0.4,0,0.15)`, `Co=(8/11,0,3/11)`이다. 배경 알파를 빼면 파랑 기여를 0.6으로 잘못 계산한다. 순서를 바꾸면 전경의 차폐율도 달라지므로 같은 결과를 기대하지 않는다.

## GPU 상태와 자산을 맞추는 절차

1. 이미지·셰이더 출력·중간 버퍼가 straight/premultiplied 중 무엇인지 적는다.
2. 목적지 RGB를 premultiplied 값 `cb=Cbαb`로 저장한 버퍼에서는 straight 전경 RGB에 `SrcAlpha/OneMinusSrcAlpha`, premultiplied 전경 RGB에 `One/OneMinusSrcAlpha`를 쓴다. 두 경우 모두 결과는 premultiplied `co`다. 배경이 불투명하면 `cb=Cb`이지만, 반투명 straight 배경을 그대로 목적지에 넣으면 배경 알파가 빠진 잘못된 결과가 된다. [Unity Blend reference](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-Blend.html)
3. 출력 알파를 저장해야 한다면 RGB 인자만 맞추고 끝내지 않는다. 알파는 `αs+αb(1-αs)`가 되도록 별도 인자를 사용한다. RGB와 동일하게 `SrcAlpha`를 알파에도 적용하면 `αs²` 항이 생긴다.
4. 중간 버퍼를 다시 합성할 때는 premultiplied `co`를 유지한다. straight 색이 필요한 출력 경계에서만 `Co=co/αo`로 변환한다. `αo=0`이면 나눗셈을 생략한다. `Co`로 바꾼 버퍼에 premultiplied 목적지용 인자를 그대로 적용하지 않는다.
5. 선형 광량 값에서의 합성과 sRGB 인코딩 값의 혼합을 구분한다. 입력 해석, 중간 HDR 범위, 출력 변환·톤 매핑을 각각 고정한다.

예를 들어 `C=0.8`, `α=0.25`의 premultiplied 채널은 0.2다. 여기에 알파를 다시 곱하면 0.05가 되어 경계가 과하게 어두워진다. 다만 어두운 테두리 모두가 이 원인인 것은 아니며 텍스처의 투명 영역 색과 필터링도 별도로 확인한다.

## 가산·곱셈이 보장하지 않는 것

| 연산 | 단순 RGB 예 | 읽어야 할 한계 |
| --- | --- | --- |
| 가산 | `0.9+0.4=1.3` | LDR에서는 잘릴 수 있고 흰 배경과 모양 대비를 보장하지 않음 |
| 곱셈 | `0.8×0.5=0.4` | 0~1 전제의 어두워짐이며 실제 그림자 광선 계산은 아님 |
| Source-over | 전경 차폐 뒤 배경 기여 | 겹치는 순서·알파 표현이 결과를 바꿈 |

효과의 인지가 목적이면 색만 더하지 말고 외곽·형태·밝고 어두운 배경에서의 대비를 함께 설계한다. 설명 화면은 입력 RGB·알파, 저장 표현, 최종 색을 나누어 보여 주면 좋다. 이 문서는 계산 모델이며 브라우저 합성·HDR 디스플레이를 실행 측정한 결과는 아니다.
