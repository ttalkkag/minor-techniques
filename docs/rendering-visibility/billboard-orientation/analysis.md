# 빌보드 정렬과 상공 시점의 퇴화

[그룹 요약](../README.md) · [조사 근거](research.md)

나무를 평면 한 장으로 만들면 정면에서는 충분히 그럴듯하지만, 카메라를 올릴 때 나무가 눕거나 갑자기 회전한다. 이는 평면을 카메라에 맞추는 규칙이 서로 다르기 때문이다. 아래 좌표계와 수치는 원리를 풀기 위한 자체 모델이며 특정 엔진의 내부 식이 아니다.

## 정렬 기준이 결과를 바꾸는 과정

평면 중심을 `p`, 카메라 위치를 `c`, 카메라의 단위 오른쪽·위 벡터를 `rc`, `uc`로 둔다. 평면의 로컬 좌표가 `(x,y)`일 때 화면 평행 방식은 `P=p+x·rc+y·uc`로 정점을 만든다. 모든 평면이 카메라의 같은 두 축을 공유하므로 화면에서 나란하다. 원근 카메라의 화면 가장자리에서는 물체에서 눈으로 향하는 방향과 평면 법선이 일치하지 않을 수 있다.

시점 지향은 각 물체마다 `n=normalize(c-p)`를 구한다. 참조 위 벡터 `u`와 직교하는 `r=normalize(u×n)`, `v=n×r`로 `P=p+x·r+y·v`를 만든다. `u`와 `n`이 평행하면 외적이 0이 되어 기저를 만들 수 없다. 같은 위치의 `c=p`도 별도 처리해야 한다.

나무의 세로축을 유지하려면 시선의 세로 성분을 먼저 없앤다.

```text
d = c - p
h = d - u(d·u)       // u는 단위 세로축
n = h / |h|          // |h|가 허용 오차보다 클 때만
r = u × n
P = p + x·r + y·u
```

예를 들어 `p=(0,0,0)`, `u=(0,1,0)`, `c=(3,4,0)`이면 시점 지향 법선은 `(0.6,0.8,0)`, 세로축 고정 법선은 `(1,0,0)`이다. 전자는 카메라 쪽으로 기울고 후자는 나무를 수직으로 세운다. `c=(0,4,0)`이면 수평 성분이 0이어서 회전 방향을 새로 정할 수 없다.

## 해결 절차

1. 나무·표식·연기 중 어떤 대상을 그리는지 정하고 화면 평행, 시점 지향, 세로축 고정 중 한 규칙을 선택한다.
2. 모델의 앞면 축과 좌표계의 좌우 방향을 확인한다. 외적 순서를 바꾸면 반대 면을 향할 수 있다. [Godot의 BillboardMode](https://docs.godotengine.org/en/4.6/classes/class_basematerial3d.html#enum-basematerial3d-billboardmode) 이름을 자체 기저의 축과 그대로 동일시하지 않는다.
3. 영벡터와 평행 상태에서는 직전 유효 방향을 유지하거나 미리 정한 수평 방향을 사용한다. 상공을 통과할 때 작은 부호 변화로 180도 회전하지 않는지 본다.
4. 반사·그림자 등 다른 시점의 패스에서도 어느 카메라를 기준으로 평면을 구성할지 정한다. 플레이 카메라와 학습용 관찰 카메라를 별도 입력으로 둔다.

## 조건, 대가, 실패 사례

| 조건 | 드러나는 한계 | 대응 |
| --- | --- | --- |
| 상공에서 나무 관찰 | 세로축 고정 평면이 얇아지고 방향이 불안정함 | 기저 퇴화 처리와 실제 기하·다각도 표현의 필요성을 구분 |
| 직교 카메라 | 물체별 위치 방향보다 평행한 시선이 적합할 수 있음 | 카메라 투영 모델에 맞는 규칙 선택 |
| 여러 평면 교차 | 정렬이 맞아도 투명 앞뒤 관계가 뒤집힘 | 합성·깊이 정책을 별도로 다룸 |
| 작은 삼각형 수, 넓은 투명 영역 | 픽셀 처리는 여전히 큼 | [잔디 비용 분석](../vegetation-cost/analysis.md)과 함께 판단 |

다각도 임포스터와 근거리 메시 LOD는 다음 비교 후보이다. 방향별 이미지의 저장량과 전환 흔적이 추가되므로 기본 빌보드보다 항상 낫다고 정하지 않는다. 관찰할 값은 법선·세로축·시선 사이 각도와 투명 중첩이며, 엔진 성능은 아직 측정하지 않았다.
