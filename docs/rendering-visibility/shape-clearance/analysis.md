# 표면 발견과 캐릭터 배치 가능성 구분

[그룹 요약](../README.md) · [조사 근거](research.md)

천장 위로 이동할 곳을 찾는 광선은 한 줄의 교차를 알려 준다. 캐릭터가 서거나 통과하려면 폭·높이·경로가 모두 맞아야 한다. 표면을 발견한 성공을 이동 허가로 바로 연결하는 것이 문제의 원인이다.

## 한 점 검사의 반례

폭 0.6m인 출구 중앙으로 광선이 통과해도 반지름 0.4m인 캐릭터는 들어가지 못한다. 원형 단면의 지름이 0.8m이기 때문이다. 천장 법선이 위쪽과 같아도 옆벽과의 간격은 이 법선으로 알 수 없다. 바닥이 평평한 것과 머리 위 공간이 충분한 것도 별개다.

자체 수직 캡슐에서 반지름 `r>0`, 전체 높이 `H≥2r`, 발 위치 `p`, 단위 위 벡터 `u`라 하면 양 끝 구의 중심은 `p+r·u`, `p+(H-r)·u`이다. 이 두 점과 `r`로 만든 부피가 옆벽·천장과 겹치는지 검사한다. `H=1.8`, `r=0.4`라면 중심은 발 위 0.4m와 1.4m이다. [Unity CheckCapsule](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Physics.CheckCapsule.html)은 이런 캡슐과 콜라이더의 겹침 질의이며 경로 전체의 이동 결과를 반환하는 API가 아니다.

## 해결 절차

1. 탐색 광선으로 천장 후보와 교차점·법선을 찾는다. 광선 길이는 스킬의 범위에 맞춘다.
2. 출구를 정의할 수 있는 표면과 두께 조건을 확인한다. 아래쪽 면 한 번의 교차만으로 위쪽 면의 높이를 추정하지 않는다.
3. 착지할 면의 단위 법선 `n`과 `u`로 `n·u≥cos(허용 경사각)`를 검사한다. 어떤 쪽 면의 법선인지 먼저 구분한다.
4. 후보 발 위치에 캐릭터 부피를 배치해 공간 여유를 검사한다. 자기 콜라이더와 의도한 접지면의 접촉 허용 정책을 명시한다.
5. 일반 이동이라면 출발→도착 경로의 형상 검사도 한다. [Unity CapsuleCast](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Physics.CapsuleCast.html)는 시작부터 겹친 콜라이더를 검출하지 않으므로 초기 겹침을 별도로 확인한다. 워프처럼 통과를 허용하는 기능은 도착 공간과 경로 차단 규칙을 따로 정한다.
6. 실제 이동 직전에 동적 장애물 상태가 바뀌지 않았는지 다시 판단한다.

이 절차는 자체 설명 모델이다. Nintendo 게임의 천장 이동 알고리즘·콜라이더 크기·허용 경사 수치가 공개 근거로 확인됐다는 뜻이 아니다.

## 조건과 대가

| 상황 | 부족한 검사 | 별도로 필요한 판단 |
| --- | --- | --- |
| 좁은 틈 | 중앙 광선만 통과 | 캐릭터의 전체 폭 |
| 낮은 방 | 바닥 면만 확인 | 전체 높이와 머리 공간 |
| 곡면·모서리 | 한 점의 법선 | 지지 영역과 안정적인 배치 |
| 이동 중 끼어듦 | 끝 위치 겹침만 확인 | 경로 sweep 또는 기능의 통과 정책 |
| 벽 안 광선 시작 | 충돌 미검출 | 엔진 내부 시작점 의미 |

더 많은 표면·형상 질의에는 비용이 들지만, 단순히 광선 수를 늘리는 것만으로 부피 검사를 대체하지는 못한다. 학습 화면은 “표면 발견/경사 통과/도착 공간/경로 허용”을 별도 상태로 보여 주는 것이 적절하다. 이 기하 예제는 원작의 알고리즘이나 엔진 질의의 실행 결과를 검증한 자료가 아니다.
