# 격자 광선 렌더러와 Doom의 BSP 구분

[그룹 요약](../README.md) · [조사 근거](research.md)

2D 지도를 3D처럼 보이게 하는 교육용 열 렌더러는 시야 질의와 같은 광선 개념을 활용한다. 그러나 고전 게임 화면이 비슷하다는 이유만으로 모든 게임이 화면 열마다 같은 격자 알고리즘을 실행했다고 결론 낼 수 없다.

## 교육용 열 렌더러가 만드는 화면

수평 지도, 일정 높이 벽, 기울지 않는 카메라부터 제한한다. 카메라 위치에서 각 화면 열의 방향으로 광선을 쏘고 가장 가까운 벽까지의 거리를 구한다. 격자에서는 다음 세로·가로 경계까지의 거리를 비교하며 한 셀씩 전진할 수 있다. 방향 성분이 0인 축의 다음 경계는 유한 후보에서 제외한다.

화면에 그릴 벽 높이는 카메라 전방 깊이 `z`에 대해 `h_screen=F·H/z`이다. `F`는 픽셀 단위 초점거리, `H`는 벽 높이다. 광선이 전방과 이루는 각이 `θ`, 광선 거리 `s`이면 단위 방향 전제에서 `z=s·cosθ`다. 광선 거리만 그대로 쓰면 평평한 정면 벽이 화면 가장자리에서 잘못 줄어든다.

자체 예에서 `F=200`, `H=2`, 전방 깊이 `z=4`이면 높이는 100픽셀이다. 60도 광선이 같은 깊이의 벽을 만나면 `s=8`이고, 이를 그대로 나누면 50픽셀로 잘못 그린다. 이 수식은 핀홀 투영의 설명용 도출이며 Doom 렌더러의 내부 상수를 복원한 것이 아니다.

## Doom 원본에서 확인한 다른 흐름

[id Software의 `r_bsp.c`](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/r_bsp.c)에서 `R_RenderBSPNode`는 현재 시점이 분할선 어느 쪽인지 구하고 앞쪽 자식을 순회한다. 뒤쪽은 `R_CheckBBox`를 통과할 때 순회하며, 말단에서는 `R_Subsector`가 벽 구간을 처리한다. 입력이 격자 셀 목록이 아니라 BSP 노드·서브섹터라는 차이를 보존해야 한다.

| 용도 | 입력 | 결과 |
| --- | --- | --- |
| 게임 시야 질의 | 관측자·표적·차폐물 | 표적의 가시성 |
| 교육용 격자 렌더러 | 격자 지도·화면 열·카메라 | 열별 벽 높이·색 |
| Doom의 해당 BSP 코드 | 노드·서브섹터·시점 | 처리할 공간·벽 구간 순회 |

## 해결과 한계

원리 소개에는 “격자 광선으로 만드는 단순 3D 화면”이라고 이름 붙이고, Doom 사례는 별도 공간 순회와 연결한다. 화면 열마다 선택 셀·광선 거리·전방 깊이를 표시하면 원근 왜곡의 원인을 추적할 수 있다. 카메라가 벽 안에 있을 때, 축과 평행한 광선, 격자 모서리 동률, 근접 벽은 별도 정책이 필요하다.

벽의 임의 높이·방 위의 방·자유 피치·투명 벽까지 기본 모델이 자동 해결하지는 않는다. 모든 고전 렌더 패스나 Wolfenstein 원본은 이번 범위에서 실행·검토하지 않았다. 위 투영 비교는 수학 예제이며 실기 성능 자료가 아니다.
