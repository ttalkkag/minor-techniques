# Crash 가시성 사전 계산 조사

[기술 분석](analysis.md) · [그룹 요약](../README.md)

## 조사 질문과 이력

카메라가 고정됐다는 말이 정지 카메라인지, 경로와 방향에 제약이 있다는 뜻인지 구분했다. 수집 ID `crash-visibility`는 2026-09-22 추가 웹 조사 항목이며 근거는 아래 개발자 회고다. 2026-09-25 해당 본문을 다시 열람해 2026-09-23 통합 판정과 대조했다. 2026-09-26에는 회고와 Epic의 사전 가시성 문서를 새로 검색·대조했다. 영상 기반 사례가 아니므로 별도의 영상 시점을 부여하지 않는다.

## 주요 자료

[Andy Gavin, Making Crash Bandicoot – part 3, 2011-02-04](https://all-things-andy-gavin.com/2011/02/04/making-crash-bandicoot-part-3/)의 `The Evolve-o-Ray` 전후가 핵심 근거다. 자유 카메라 실험에서 분기 레일과 사전 계산으로 방향을 정했다는 대목, 카메라가 캐릭터 옆·앞·뒤를 이동했다는 대목, SGI에서 visibility/sort를 구했다는 대목을 2026-09-25 재열람했다. 이어지는 처리 시간과 레벨 제작 작업은 실행 비용을 제작 비용으로 옮긴다는 해석을 뒷받침한다. 2026-09-26 웹 열람 도구에서는 회고 본문의 후속 요청이 시간 초과되어, 같은 공개 URL의 HTML을 직접 받아 해당 문단을 재확인했다.

일반적인 비용 교환은 [Epic의 Unreal Engine 4.27 Precomputed Visibility Volume](https://dev.epicgames.com/documentation/unreal-engine/precomputed-visibility-volume?application_version=4.27)의 도입부·통계·제한 절과 대조했다. 이 문서는 실행 시 메모리와 제작 시간을 쓰는 대신 가시성 질의 비용을 줄이며, 이동 물체에는 제약이 있음을 설명한다. 이는 현대 엔진의 별도 사례이며 Crash의 내부 구현 근거로 사용하지 않는다.

## 주장별 판단

| 주장 | 판단 | 이유 |
| --- | --- | --- |
| 카메라가 한 곳에 정지했다 | 채택하지 않음 | 회고는 세계 안의 경로 이동과 분기를 설명함 |
| 카메라 제약과 배경 가림이 가시성 사전 계산을 도왔다 | 역사 사례로 채택 | 개발 당사자의 직접 회고 |
| 게임 전체 실행 비용이 0이었다 | 채택하지 않음 | 가시성·정렬 문맥의 표현을 모든 게임 작업으로 확장할 수 없음 |
| 회고의 폴리곤 수가 콘솔의 보편적 한계다 | 채택하지 않음 | 특정 게임 제작 조건의 수치 |
| 교육용 구간 목록이 원작 알고리즘과 같다 | 채택하지 않음 | 공개 회고만으로 자료구조와 압축 규칙을 복원하지 못함 |

## 비교할 설계 조건

“전체 배경 제출/사전 목록/현재 시점 재계산”을 비교하고 경로 이탈·가림막 이동·동적 물체를 실패 조건으로 다룬다. 관찰 화면에 생략된 배경을 남기면 “월드 삭제”와 “이번 화면 미제출”을 구분할 수 있다. 분석의 구간 합집합과 표본 누락 예는 자체 설명이며 회고 인용이 아니다.

## 아직 확보하지 않은 근거

원작 코드·레벨 데이터·압축기·동적 객체 처리와 실기 성능은 확인하지 않았다. 유한한 카메라 표본이 연속 구간을 얼마나 잘 대표하는지는 자체 구현에서 별도 판단해야 한다. 이번 작업은 공개 글 열람이며 원작 실행이나 원본 영상 재시청이 아니다. 회고의 게임 이미지와 캐릭터 자산은 복제하지 않는다.
