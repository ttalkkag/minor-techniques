# 카메라 경로를 제한해 가시성을 미리 구하기

[그룹 요약](../README.md) · [조사 근거](research.md)

복잡한 배경의 가시성과 정렬을 매 프레임 계산하기 어려울 때, 허용되는 카메라 위치를 제한하면 일부 계산을 제작 단계로 옮길 수 있다. Crash Bandicoot의 레일 카메라는 이 교환을 설명하는 역사 사례다. 아래 집합 모델은 원작 데이터 형식의 재현이 아니다.

## 왜 경로 제한이 사전 계산을 가능하게 하나

자유 카메라는 위치·방향·시야각의 조합이 많다. 카메라가 경로 `c(s)`와 정해진 방향 규칙을 따르면 상태를 주로 경로 진행률 `s`로 구분할 수 있다. 정적 배경에 대해 그 상태에서 필요한 물체 집합 `V(s)`를 제작 중 구하고 실행 때 불러오는 방식이 가능해진다.

교육용 구간 `Iᵢ`에 저장할 안전한 집합은 `Bᵢ ⊇ ⋃ V(s), s∈Iᵢ`이다. 구간 중 필요한 대상을 모두 포함해야 한다. 구간 시작·끝 두 장만 검사했다고 연속 구간 전체의 포함 관계가 증명되지는 않는다. 중간에서 작은 틈이 열릴 수 있기 때문이다.

예를 들어 구간 A가 `{나무, 앞벽}`, B가 `{앞벽, 문, 뒤방}`을 필요로 한다면 전환 경계에서 합집합 `{나무, 앞벽, 문, 뒤방}`을 쓰는 것은 누락을 줄이는 보수적 선택이다. 다만 이 합집합도 각 구간의 원래 목록이 충분하다는 전제가 필요하다.

## 해결 절차

1. 카메라 경로·방향·시야각과 움직이지 않는 배경의 범위를 고정한다.
2. 자체 장면에서는 여러 기준 시점의 가시성을 수집하고 전환 구간을 따로 확인한다. 유한 표본만 썼다면 정확한 연속 가시성 해법으로 표시하지 않는다.
3. 실행 시 현재 구간의 목록을 선택한다. 분기와 되돌아가기에서도 같은 상태가 같은 목록을 선택하게 한다.
4. 캐릭터·이동 상자·열리는 문 등 동적 상태는 별도로 처리한다. 문이 열린 상태가 준비되지 않았다면 목록을 갱신하거나 더 넓은 목록을 사용한다.
5. 플레이 카메라는 목록 선택에, 관찰 카메라는 레일·가림막·제출 대상을 보여 주는 데 사용한다.

Andy Gavin의 [2011년 회고](https://all-things-andy-gavin.com/2011/02/04/making-crash-bandicoot-part-3/)는 분기 레일, SGI에서의 가시성·정렬 사전 계산과 가림을 위한 배경 배치를 설명한다. 화면 제출을 줄이는 절차와 실제 그리는 작업 자체가 없어지는 것은 다르다.

## 무엇을 얻고 무엇을 포기하나

| 바꾼 조건 | 예상되는 실패 | 대응 |
| --- | --- | --- |
| 카메라가 레일 밖으로 나감 | 기존 목록에 없던 면·물체가 보임 | 자유 카메라용 계산 또는 허용 영역 확대 |
| 가림막 이동·파괴 | 과거에 가려진 배경 누락 | 상태별 목록·재계산·보수적 목록 |
| 시야각 확대 | 화면 가장자리가 목록 범위를 벗어남 | 사전 계산 조건에 시야각 포함 |
| 구간을 너무 잘게 나눔 | 목록 저장량과 제작 시간이 커짐 | 구간 크기와 중복 데이터의 균형 |

원문의 폴리곤 수는 해당 제작 사례의 수치이며 PlayStation 전체의 고정 한계가 아니다. 목록 압축, 동적 대상의 정확한 처리, 모든 정렬 규칙은 미확인이다. 실험에서는 기준 화면의 누락과 제출량·사전 계산 시간·저장량을 따로 기록해야 하며 원작 실행 성능으로 환산하지 않는다.
