# 터널링과 CCD 리서치

[상세 분석](analysis.md) · [실험 설계](experiment.md) · [그룹 요약](../README.md)

수집 ID는 `collision-tunneling`이다. 특정 영상이 아닌 아래 공식 CCD 문서를 근거로 스텝 끝 겹침과 선형 경로 검사의 차이를 다룬다. 자료별 열람 시점과 범위는 다음과 같다.

## 공개 자료의 주장과 범위

| 자료 | 확인한 대목·상태 | 이 문서의 판단 |
| --- | --- | --- |
| [Unity Continuous collision detection](https://docs.unity3d.com/6000.0/Documentation/Manual/ContinuousCollisionDetection.html) | 2026-09-26 본문 열람, Unity 6.0: 스텝 사이 충돌의 예측과 비용, 정확성의 한계 | CCD를 완전한 물리 정확성 보장으로 소개하지 않는다. |
| [Unity Sweep-based CCD](https://docs.unity3d.com/6000.0/Documentation/Manual/sweep-based-ccd.html) | 2026-09-26 본문 열람, Unity 6.0: `Understand sweep-based CCD`, TOI 설명, 마지막 회전 제한 문단 | 선형 궤적의 최초 충돌을 계산하는 원리와 회전 플리퍼의 반례를 채택한다. Unity 모드 조건을 모든 엔진의 공통 사양으로 쓰지 않는다. |
| [Unity Speculative CCD](https://docs.unity3d.com/6000.0/Documentation/Manual/speculative-ccd.html) | 2026-09-26 본문 열람, Unity 6.0: AABB 확장, false collision, 마지막 missed collisions 예시 | 각운동 후보·잘못된 법선·예측 범위 밖 누락을 구분한다. sweep보다 항상 정확하다는 설명을 배제한다. |

공식 문서의 비용 설명은 알고리즘을 고를 때의 배경이다. 브라우저 실험의 실행 시간이나 특정 게임의 개선 비율을 측정한 출처가 아니다. Unity 도해를 페이지에 복제하지 않고 자체 단면 표시를 사용한다.

## 실험 범위

스텝 끝 겹침과 선형 경로의 최초 접촉을 같은 조건에서 비교한다. [상세 분석](analysis.md)은 접촉 구간·시각·경계 처리와 수치 예를 제공한다.

실험 명세에서 조절하는 값은 속도·벽 두께·검사 빈도·반지름이다. 발사 위치·방향은 고정한다. 수식이 반대 방향을 지원한다는 사실과 사용자 화면에서 방향을 조절한다는 요구사항을 구분한다. 회전 막대·Speculative CCD는 이 실험의 범위에 포함하지 않는다.

## 자체 도출과 근거

접촉 구간 확장과 최초 접촉 비율은 정지한 평평한 벽·수평 직선 운동이라는 가정에서 직접 도출했다. Unity 내부 알고리즘을 그대로 옮긴 것이 아니다. 기본값과 120 Hz 계산은 [실험 설계](experiment.md)의 재현 조건으로 연결한다. 초기 겹침은 접촉 시각 0, 닫힌 경계에 정확히 도달하면 스텝 끝 접촉이며, 반대 방향은 벽의 오른쪽 확장 경계를 사용한다. 같은 물리 틱에 같은 입력을 주면 표시 프레임을 나눈 방식이 달라도 같은 계산을 수행한다. 이는 모델의 성질이며 엔진 성능이나 사용자 이해도를 측정한 결과가 아니다.

## 남은 조사

회전 사례를 추가하려면 선형 이동과 각운동을 각각 조절할 모델·형상을 먼저 정해야 한다. 움직이는 상대, 충돌 후 남은 시간, 여러 접촉은 현재 단일 벽 모델과 다른 조건이다. 어떤 엔진의 CCD를 소개할 때는 지원 형상·모드 조합·버전을 명시하고 해당 엔진에서 별도로 확인해야 한다.
