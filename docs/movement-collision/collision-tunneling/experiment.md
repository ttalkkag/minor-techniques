# 실험: 벽을 통과한 총알

[원인과 해결 분석](analysis.md) · [자료와 판단](research.md)

이 명세는 조절값·화면·예상 결과와 두 검사 방식의 비교 조건을 정의한다.

## 학습 목표

사용자가 ‘검사한 두 위치에서는 벽에 닿지 않았지만, 두 위치 사이에는 충돌이 있었다’를 설명할 수 있게 한다. 물리 검사 빈도, 화면의 재생 속도, 카메라 시점이 각각 무엇을 바꾸는지도 구분한다.

## 기준 장면과 비교 조건

동일한 탄환과 벽을 나란히 표시한다. A는 스텝 끝점의 겹침을 검사하고, B는 직선 경로의 최초 접촉을 검사한다. 위치·형상·속도·시간 간격은 공유한다. 시작 중심은 `-5 m`, 벽 중심은 `0 m`, 탄환은 오른쪽으로 일정 속도로 움직인다.

| 조절값 | UI 범위·간격 | 초기값 | 관찰할 변화 |
| --- | --- | --- | --- |
| 탄환 속도 | 5~150 m/s, 5 간격 | 90 m/s | 스텝 사이 이동 거리 |
| 벽 두께 | 0.1~3 m, 0.05 간격 | 0.3 m | 중심이 접촉할 수 있는 구간 |
| 1초당 물리 검사 | 5~240회, 5 간격 | 10회 | 위치 샘플 수·감지 시각 |
| 탄환 반지름 | 0.05~0.6 m, 0.01 간격 | 0.16 m | 확장한 접촉 구간 |

조건을 바꾸면 이전 결과를 초기화한다. ‘벽 통과 예시’는 초기값, ‘촘촘한 검사’는 같은 조건에서 검사 빈도만 120회/s로 설정한다. 관찰 속도 `0.1×/0.25×/1×`는 진행을 천천히 볼 배율이며 물리 간격을 변경하지 않는다.

## 화면과 조작

전체 장면을 중심으로 왼쪽 햄버거 메뉴에서 조건을 조절한다. 메뉴는 접을 수 있고 모바일에서는 접힌 상태로 시작한다. 3D는 드래그 회전·휠/핀치 확대·오른쪽 드래그 또는 두 손가락 이동과 시점 초기화를 제공한다.

2D 단면에서는 이전 위치, 충돌이 없을 때의 예정 위치, 이동 구간, 최초 접촉을 읽는다. A와 B의 경로를 같은 축척으로 표시해야 비교가 가능하다. 3D를 사용할 수 없을 때는 동일한 계산의 2D 표시로 전환한다.

‘실험 재생/일시 정지’, ‘한 스텝’, ‘실험 초기화’로 시간을 제어한다. ‘왜 이런 일이 생길까요?’ 설명창은 문제→원인→해결→대가를 담는 팝업이다. 설정은 데스크톱에서 장면 옆 패널, 모바일에서 장면 위 레이어로 열린다. 닫기/Escape로 다시 장면을 볼 수 있다.

## 관찰 순서와 예상 결과

1. **벽 통과 예시 → 한 스텝.** 예정 이동 `-5→4 m`를 보고 A의 누락과 B의 접촉을 비교한다. B 중심은 `-0.31 m`, 접촉 시각은 약 `0.052111 s`다.
2. **2D 단면.** 벽 표면 `-0.15 m`와 탄환 중심 `-0.31 m`의 차이가 반지름임을 확인한다. 예정 위치 점선이 실제 정지 위치가 아님을 구분한다.
3. **촘촘한 검사 → 재생.** A는 `0.25 m`, 약 `0.058333 s`에 감지한다. B는 처음과 같은 접촉을 찾는다. 두 검사 모두 성공해도 감지 위치·시각은 같지 않다.
4. **값 하나씩 변경.** 속도·두께·반지름·검사 빈도에 따라 샘플과 접촉 구간의 관계가 어떻게 변하는지 찾는다. 높은 빈도 한 번의 성공을 모든 조건의 보장으로 확대하지 않는다.
5. **재생 속도와 시점만 변경.** 같은 물리 조건의 결과가 유지되는지 관찰한다. 화면을 천천히 보는 것과 더 세밀하게 계산하는 것을 구분한다.

## 수치의 의미와 범위

결과 시간은 A의 스텝 끝 감지 시각, B의 스텝 안 최초 접촉 시각이다. 재생 막대의 시간은 완료한 물리 스텝 시각이라 B의 접촉 시각과 다를 수 있다. 검사 횟수는 해당 판정 함수 호출 수이며 CPU 시간·FPS 결과가 아니다.

충돌 후 튕김·마찰·회전·가속·움직이는 벽은 다루지 않는다. 시작 위치·발사 방향·벽 위치는 고정 조건이다. 실제 사용자 학습 효과는 아직 측정하지 않았다.
