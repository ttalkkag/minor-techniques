# 전투 판정 리서치

[상세 분석](analysis.md) · [그룹 요약](../README.md)

수집 ID는 `hitboxes`다. 영상 근거는 2026-09-22의 대표 화면·자막·OCR 분석이며, 2026-09-26에 열람한 Godot 문서는 영역 감지와 갱신 시점의 근거다.

## 출처별 근거

| 출처 | 구체 대목 | 지지하는 주장 |
| --- | --- | --- |
| [피격 판정 영상](https://www.youtube.com/watch?v=hUpx8lUaiDU&t=24s) | 기존 분석의 00:24 공격·피격 박스, 00:36 준비 후 활성, 01:00 히트스톱 | 판정 도형·활성 시간·타격 연출을 나눠 설명할 근거다. |
| [Godot Area2D](https://docs.godotengine.org/en/stable/classes/class_area2d.html) | 09-26 stable 본문 열람: `monitoring`, `monitorable`, `get_overlapping_areas()`, `get_overlapping_bodies()` | 영역 감지와 레이어/마스크, 목록의 물리 단계 갱신을 확인했다. 전투 피해를 확정하는 기능의 명세가 아니다. |

영상의 모든 프레임을 재검토하거나 영상 속 게임의 실제 판정을 실행하지는 않았다.

## 분석에 반영한 판단

이동·공격·피격 영역은 서로 다른 역할이다. 영상 사례를 일반화해 ‘판정을 넓히면 항상 공정하다’고 쓰지 않는다. 관대함과 공정성은 상대에게 보이는 피드백·장르 조건을 포함한 별도 평가다.

Area2D의 겹침 목록 갱신과 피해 중복 방지는 서로 다르다. 목록을 제때 읽어도 한 적의 여러 영역을 다른 대상으로 취급하면 중복 피해가 생긴다. 상세 분석에 추가한 공격 ID·대상 ID·다단 회차는 자체 설계이며 Godot가 자동 제공한다는 설명이 아니다.

히트스톱 중 입력·UI의 시계를 나누는 것도 프로젝트의 설계 후보다. 모든 원작이 같은 시계나 버퍼 만료 정책을 사용한다는 근거는 없다.

## 후속 질문

- 원작을 특정하면 공격별 프레임 데이터와 충돌체 자료를 확보해야 한다. 현재 예시의 틱 수는 임의값이다.
- 빠른 무기 판정은 회전 궤적·형상·시간 간격에 맞는 추가 조사와 구현이 필요하다.
- 경쟁 상황에서 판정 조절이 읽기 쉬움과 공정성에 주는 영향은 사용자 관찰로 확인할 문제다.

영상 캡처는 이 문서에 복제하지 않는다. 공개 화면의 도형 비교와 시간축은 자체 제작 대상으로 남긴다.
