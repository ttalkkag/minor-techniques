# 접지 유예와 입력 버퍼

[그룹 요약](../README.md) · [출처와 판단](research.md)

원자료: `coyote-time`. 이 문서는 두 시간 창의 설계를 다루며 예시 시간은 게임별 권장값이 아니다.

## 왜 눌렀는데 점프하지 않는가

점프를 `지금 접지 중이고 이번 틱에 버튼을 눌렀다`로만 승인하면 발판 이탈 직후와 착지 직전 입력이 모두 사라진다. 전자는 접지가 너무 일찍 끝났고, 후자는 입력이 너무 일찍 왔다. 플레이어에게 비슷하게 느껴져도 저장해야 할 사건이 다르다.

코요테 타임은 마지막 접지 사실을 잠시 인정한다. 입력 버퍼는 아직 쓰지 않은 점프 입력을 잠시 보관한다. 위치를 모서리 밖으로 옮기는 [코너 보정](../corner-correction/analysis.md)과는 별도 규칙이다.

## 최소 상태와 승인 조건

필요한 상태는 마지막 접지 시각 `g`, 마지막 누름 시각 `j`, 접지 유예의 사용 가능 여부, 입력의 소비 여부다. 현재 시각 `t`, 접지 유예 길이 `C`, 입력 유효 길이 `B`에 대해 다음을 설계 예로 쓸 수 있다.

```text
접지 가능 = 현재 접지 OR (유예 미소비 AND 0 ≤ t - g ≤ C)
입력 가능 = 입력 미소비 AND 0 ≤ t - j ≤ B
점프 승인 = 접지 가능 AND 입력 가능 AND 점프 가능한 캐릭터 상태
```

접지나 누름 기록이 없는 초기 상태는 해당 자격을 사용 불가로 둔다. 마지막 접지 시각만 저장하면 점프 직후에도 `t-g≤C`가 남아 연타로 공중 재점프할 수 있다. 승인 시 입력과 접지 유예를 함께 소비하고, 실제 착지 때 접지 자격을 다시 부여해야 한다. ‘버튼을 누르고 있음’과 ‘새 누름 이벤트’를 구분한다. 계속 누르는 동안 매 틱 새 입력을 만들면 의도와 다른 자동 점프가 된다.

## 시간축으로 보는 두 사례

| 사건 | 상태 | 예시 결과 |
| --- | --- | --- |
| 마지막 접지 1.000초 → 입력 1.050초 | `C=0.080초`, 버퍼 미소비 | 이탈 후 50ms이므로 유예 점프를 승인할 수 있다. |
| 입력 2.000초 → 착지 2.060초 | `B=0.100초`, 접지 자격 복구 | 먼저 저장한 입력을 착지에서 한 번 소비한다. |
| 입력 2.000초 → 착지 2.120초 | 같은 B | 만료된 입력은 실행하지 않는다. |

고정 틱 구현에서는 시각을 틱으로 양자화한다. 예를 들어 `C=80ms`, `h=1/60초`일 때 틱 경계와 이벤트를 어느 틱에 배정하는지에 따라 마지막 허용 입력이 달라진다. 포함 경계 `≤`와 입력 배치 정책을 함께 적어야 수치만 같은 구현 사이의 차이를 설명할 수 있다.

## 갱신 순서

1. 누름 이벤트를 한 번 기록한다. 입력 버퍼 정책을 ‘새 누름만’ 또는 ‘유지까지 필요’ 중 선택한다.
2. 이동 결과의 접지 상태와 마지막 접지 기록을 갱신한다. 이전 접지와 새 접지를 구분한다.
3. 착지·벽 점프·대시 등 경쟁하는 행동의 우선순위를 정하고, 승인된 행동만 입력을 소비한다.
4. 점프가 승인되면 수직 속도를 부여하고 접지 자격을 소비한다. 사망·장면 전환·리스폰 때 오래된 입력이 남지 않게 한다.

이 순서는 가능한 설계다. 이동 전에 점프를 평가하는 구현이라면 착지 틱 처리 방법이 달라진다. 엔진 신호 순서와 무관하게 같은 결과라고 가정하지 않는다.

## 선택의 대가와 관찰 항목

유예를 늘리면 허용 가능한 실수 폭이 넓어진다. 동시에 이미 포기한 입력이 착지 순간 실행되거나, 좁은 지형에서 원하지 않은 점프가 이어질 수 있다. 벽 점프와 접지 점프가 동시에 가능할 때 어느 쪽을 선택하는지는 별도 게임 규칙이다.

시간축에 접지·누름·승인·만료를 각각 표시하면 실패 이유가 보인다. 길이를 하나씩 0으로 만들고 경계 전후·연타·계속 누름·착지 없는 낙하를 비교하는 것이 핵심이다.
