# 규칙 점수로 기술 선택하기 — 분석

[그룹 요약](../README.md) · [상세 분석](analysis.md) · [리서치](research.md)

## 문제와 원인

기술의 타입이 유리하다는 이유만으로 가점을 주면 피해를 주지 않는 기술에도 공격 상성을 적용할 수 있다. 이미 걸린 상태 이상을 다시 시도하거나 PP가 없는 기술을 선택하는 문제도 생긴다. 선호를 높인다는 설명과 숫자 점수를 높인다는 설명을 섞으면 비용 점수의 방향이 뒤집힌다.

## 역사 사례와 독립 개선 모형

공개된 [Gold/Silver 재구성 코드의 AIChooseMove](https://github.com/pret/pokegold/blob/master/engine/battle/ai/move.asm)는 낮은 비용을 선호한다. 야생·통신·고정 기술 상태는 앞에서 별도 처리한다. 기본 점수를 설정하고 사용 불가 기술을 불리하게 처리한 뒤 트레이너별 scoring layer를 적용하며 최저점 후보를 남겨 난수로 선택한다. 이는 커뮤니티 재구성 소스의 정적 관찰이며 제작사 원본 공개 코드나 실행 재현 결과가 아니다.

독립적인 설명 모형은 사용 가능 여부와 선호를 더 명시적으로 분리할 수 있다.

```text
기술 후보 → 사용 가능 검사 → 규칙별 비용 변화 → 최소 비용 집합 → 동점 추첨
```

이 흐름을 원작의 메모리 구조와 완전히 동일하다고 부르지 않는다. 원작 소스는 사용 불가 기술에 불리한 점수를 주는 방식도 포함하지만 설명 모형은 아예 제외하는 선택을 한다. 개선 모형과 원작 재현 모드를 섞으면 오류를 고친 줄 알면서 역사적 동작을 왜곡할 수 있다.

## 점수 변화의 구체 예

교육용 기본 비용을 모두 20으로 놓고, 상대는 이미 독 상태이며 자신의 체력은 낮다고 하자.

| 기술 | 사용 가능 | 규칙에 따른 변화 | 최종 |
| --- | --- | --- | --- |
| 일반 공격 | 가능 | 중립 | 20 |
| 독 부여 | 가능하지만 중복 효과 | 중복 상태 +10 | 30 |
| 회복 | 가능 | 체력 부족 −5 | 15 |
| 강한 공격 | PP 0 | 후보 제외 | 없음 |

회복 15가 선택된다. 체력이 가득 차면 회복 규칙을 다시 평가해야 한다. 같은 기술이 여러 규칙에 걸리면 초기값, 각 변화량, 최종값을 따로 남긴다. 최소 후보가 여러 개일 때만 추첨하며 그 단계에서만 난수를 소비한다는 독립 정책도 가능하다. 재구성 코드의 `.ChooseMove`는 최소 후보가 하나여도 난수 호출로 슬롯을 골라 유효 후보가 나올 때까지 반복한다. [scoring layer 내부의 확률적 조정](https://github.com/pret/pokegold/blob/master/engine/battle/ai/scoring.asm)도 있으므로 독립 정책을 원작과 같은 호출 순서라고 설명하지 않는다.

## 해결 절차

1. 기술 ID, 효과 종류, 공격력, 사용 가능 조건을 구분한다. 피해가 없는 기술에 공격 타입 효율만 적용하지 않는다.
2. PP 0·금지·고정 행동·빈 기술 목록의 처리를 먼저 결정한다. 선호 점수 계산으로 불가능한 행동을 가능하게 만들지 않는다.
3. 규칙별 비용 방향을 하나로 통일한다. ‘선호 증가’는 비용 감소라는 점을 수치와 함께 보여 준다.
4. 첫 턴과 이후 턴, 상태 이상 유무, 최대 체력, 동점의 경계를 비교한다.
5. 반복 행동을 줄이려고 난수를 추가할 때 올바른 후보 집합과 효과 조건부터 확인한다. 무작위성이 잘못된 규칙 자체를 고치지는 않는다.

## 같은 영상의 데이터·압축 배경

시간대별 조우 테이블과 명시적인 기술·아이템 데이터는 더 많은 정보를 저장하는 대신 세부 규칙을 표현할 여지를 늘린다. 이 데이터 선택과 전투 점수 계산은 다른 문제다. 압축 역시 크기만이 아니라 해제 시간과 작업 메모리를 함께 본다. 수집 연구가 대조한 [decompress.asm](https://github.com/pret/pokegold/blob/master/home/decompress.asm)은 리터럴·반복·기존 출력 참조 명령의 처리 근거다. 영상의 ‘해제 시간 절반’ 수치를 독립 측정 결과로 채택하지 않는다. 더 자세한 자원 절충은 [실행 비용·자원](../../runtime-resources/README.md)에 연결한다.

## 선택과 한계

몇 개의 기술에는 규칙 표가 설명과 디버깅에 적합하다. 행동이 이동·탐색·전투 단계로 늘면 상태기 같은 구조를 비교할 수 있지만 그것이 더 좋은 전략을 학습해 주지는 않는다. 가중 규칙은 설계자가 넣은 기준을 실행하며, 상대를 학습한 신경망 AI와 다르다. 실제 원작 행동을 재현하려면 언어·지역·판본과 코드 revision, 난수 상태까지 맞춰야 한다.
