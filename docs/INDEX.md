# 메인 페이지: 실험 목록

[문서 목차](README.md)

게임 실험실의 첫 화면에서 어떤 현상을 관찰하고 무엇을 조절할 수 있는지 확인한 뒤, 원하는 실험으로 들어간다. 목록에서는 선택에 필요한 정보만 보여주고 원인·해결 설명과 조작은 상세 페이지에서 제공한다.

이 문서는 목록의 목적·구성 요소·콘텐츠·노출 정책·동작을 정의한다. 색상·글꼴·크기·간격, 공통 헤더와 버튼, 썸네일 제작 규칙은 [프로젝트 디자인 기준](../DESIGN.md)을 따른다.

## 목록의 단위

- 항목 하나는 직접 조작할 수 있는 개별 실험이다. 물리·소리 같은 넓은 분야를 하나의 실험으로 묶지 않는다.
- 제목은 관찰할 현상을 드러내고, 짧은 설명에는 바꿔볼 조건을 적는다. 예: **벽을 통과한 총알?** — 속도와 검사 간격을 바꾸며 충돌을 비교한다.
- 분류·관찰 방식·관련 게임은 태그로 표시한다. 예: `물리`, `3D 관찰`, `2D 단면`.
- 상세 페이지가 준비된 실험 중 기본 목록에 표시할 항목을 명시적으로 선택한다. 페이지가 존재한다는 이유만으로 모두 노출하지 않는다.

## 화면 구성

상단에는 상세 페이지와 같은 공통 헤더를 사용한다. 좌측에는 텍스트 브랜드 **Game lab**, 우측에는 목록 보기 전환 버튼을 둔다. 목록에는 햄버거 메뉴·설명·전체 초기화 버튼을 추가하지 않는다. 별도 로고와 본문의 **실험 목록** 소제목도 표시하지 않는다.

본문은 실험 목록으로 구성한다. 화면 너비에 맞춰 표시하며 길어지면 페이지를 스크롤한다.

| 보기 | 표시할 내용 | 용도 |
| --- | --- | --- |
| 썸네일 보기 — 기본 | 대표 그림·제목·짧은 설명·태그·이동 화살표 | 어떤 현상을 다루는지 시각적으로 선택 |
| 간단 목록 보기 | 번호·제목, 우측 태그 | 여러 실험을 빠르게 훑어 선택 |

보기 전환은 **네모 아이콘**과 **가로줄 아이콘**으로 표시한다. 선택한 버튼을 구분하고, 접근성 이름과 선택 상태를 제공한다. 보기만 바뀌며 실험의 순서와 상세 연결은 동일하다.

썸네일 보기에서는 좌측에 그림, 우측에 제목과 짧은 설명을 둔다. 태그는 카드 좌측 하단, 이동 화살표는 우측 하단에 배치한다. `실험 열기` 문구는 붙이지 않는다. 간단 목록에서는 썸네일·설명·화살표를 숨긴다.

좁은 화면에서는 썸네일과 설명을 세로로 배치하고, 간단 목록의 태그는 공간이 부족하면 다음 줄로 내려 제목과 겹치지 않게 한다.

## 항목에 필요한 정보

| 정보 | 역할 |
| --- | --- |
| 고유 식별자·상세 주소 | 같은 실험을 식별하고 상세 페이지로 연결 |
| 제목 | 관찰할 현상을 짧게 제시 |
| 짧은 설명 | 바꿔볼 조건과 비교할 결과를 안내 |
| 썸네일 | 대표 현상이나 비교 장면을 간단한 그림으로 제시 |
| 태그 | 분류·관찰 방식·확인된 게임 사례를 구분 |

두 보기에서 같은 데이터를 사용한다. 번호는 고정 식별자가 아니라 현재 보이는 순서대로 `01`부터 붙이는 값이다.

### 태그 구성

- 분류는 첫 번째 태그로 한 번만 표시하고 별도의 분류 라벨을 중복 배치하지 않는다.
- 태그 하나는 하나의 개념만 나타낸다. `지연 보상`, `3D 관찰`처럼 띄어쓰기가 있는 용어나 게임의 정식 이름도 하나의 태그로 취급한다.
- `네트워크와 저장`, `렌더링·재질`처럼 서로 다른 개념을 묶지 않는다. 해당 실험에 둘 다 필요하면 각각의 태그로 분리한다.
- 해당 기법을 활용한 사례가 확인된 게임은 구체적인 게임 이름을 표시한다. 긴 정식 이름도 하나의 태그로 유지한다.

## 노출 정책과 관리

실험 정보는 `src/experiments/{id}/entry.json`에서 관리한다. 기본 목록에 표시할 항목은 [experiments.ts](../src/data/experiments.ts)의 `listedExperimentIds`에서 지정한다.

| 접근 방식 | 표시할 항목 |
| --- | --- |
| `/` | 기본 목록에 지정한 실험 |
| `/?display=all` | 숨긴 항목을 포함한 전체 실험 |

현재 기본 목록은 `collision-tunneling`과 `lag-compensation`이다. 숨김은 목록에서의 노출 여부이며, 상세 페이지 접근을 제한하는 기능이 아니다.

## 순서와 보기 전환

- 새 방문과 새로고침에서는 썸네일 보기로 시작하고 순서를 무작위로 정한다.
- 브라우저가 뒤로가기·앞으로가기로 기존 목록 화면을 복원하면 보기 방식은 유지하고 순서는 다시 섞는다.
- 썸네일·간단 목록의 보기 버튼만 전환할 때는 순서와 노출 항목을 유지한다.
- 순서가 바뀌면 보이는 항목의 번호도 다시 매긴다. 무작위 선택이므로 같은 순서가 연속해서 나올 수 있다.

## 상세 이동과 접근성

- 카드나 행 전체가 해당 실험 상세 페이지로 연결된다. 태그와 화살표는 별도의 버튼으로 만들지 않는다.
- 두 보기 전환과 실험 선택은 키보드로도 사용할 수 있고, 초점과 선택 상태가 보여야 한다.
- 간단 보기에서 숨긴 설명은 카드의 접근성 설명에서도 제외한다.
- 상세 페이지의 브랜드 링크로 목록에 돌아올 수 있어야 한다.

## 확인 기준

- 기본 목록은 지정한 항목만, `?display=all`은 전체 항목을 표시하는가.
- 새 방문·새로고침·브라우저 화면 복원에서 순서를 다시 섞는가.
- 보기 전환만 할 때는 순서·노출 항목·상세 주소가 유지되는가.
- 번호가 현재 표시 순서와 일치하고 두 보기의 정보가 같은 실험을 가리키는가.
- 공통 헤더 우측에 보기 버튼이 있고, 본문 소제목과 불필요한 버튼이 없는가.
- 카드 전체와 키보드 조작으로 상세 페이지에 들어갔다가 목록으로 돌아올 수 있는가.

화면의 색상·크기·여백·넘침·썸네일 가독성은 [디자인 확인 기준](../DESIGN.md#확인-기준)으로 검증한다.
