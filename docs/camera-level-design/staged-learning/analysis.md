## 왜 공간 배치만으로 학습이 전달되지 않는가

처음 보는 적, 보상, 이동 조작을 동시에 요구하면 실패가 무엇 때문인지 분리하기 어렵다. 안전한 평지에서 방향 입력을 익히고, 하나의 적으로 점프를 시도하고, 보상으로 접촉 결과를 경험하게 하면 한 번에 추론할 대상이 줄어든다. 다만 이것은 학습 기회를 만드는 설계이고 모든 사람이 같은 행동을 한다는 보장은 아니다.

Mario 1-1의 버섯은 적과 외형이 비슷해 피하려는 대상이 될 수 있다. 파이프에서 돌아오는 움직임과 머리 위 블록이 회피 행동을 제한하면 접촉할 가능성이 생긴다. 접촉 이후 크기 변화가 보상임을 보여 주는 구조다. 이 의도는 Miyamoto의 직접 인터뷰에 근거한다. [Nintendo 개발자 인터뷰](https://www.nintendo.com/en-gb/Iwata-Asks/Iwata-Asks-New-Super-Mario-Bros-Wii/Volume-1/4-Letting-Everyone-Know-It-Was-A-Good-Mushroom/4-Letting-Everyone-Know-It-Was-A-Good-Mushroom-210863.html)

## 레벨 규칙과 이동 규칙을 나눈다

레벨은 시도할 공간과 실패 비용을 정한다. 캐릭터 제어는 같은 입력으로 얼마만큼 움직일지를 정한다. 자체 모형의 가속도 a와 최고 속도 vmax를 두더라도 입력을 놓았을 때의 감속과 반대로 눌렀을 때의 제동을 같게 둘 필요는 없다. 평지의 일정 제동 b에서 정지거리 `v²/(2b)`를 계산하면 왜 제동을 바꾼 뒤 같은 구멍이 더 어려워질 수 있는지 설명할 수 있다. 이는 마찰·충돌·공중 제어를 생략한 자체 연속 모형이다.

가변 점프에서는 버튼 유지, 상승 중 버튼 해제, 낙하, 공중 횡이동을 구분한다. 같은 착지점을 유지하려면 높이뿐 아니라 체공시간과 수평 속도도 봐야 한다. 원영상의 낙하 중력 3배나 버튼 해제 시 속도 처리를 원작 상수로 고정하지 않는다.

## 해결 절차와 관찰 예

1. 학습시킬 행동을 한 문장으로 정한다. 예: ‘이 물체에 닿으면 이득을 얻는다.’
2. 그 행동을 처음 요구하는 장소의 위험·실패 비용을 낮춘다. 바닥 있는 틈과 바닥 없는 낭떠러지는 다른 실패 조건으로 둔다.
3. 성공 직후 결과를 시각·소리 등으로 알려 보상과 입력을 연결한다.
4. 같은 행동을 조금 다른 공간에서 다시 요구하고 이후 다른 위험과 조합한다.
5. 이동 상수를 바꿀 때는 동일 입력 기록의 제동거리·점프 최고점·착지점을 먼저 비교한 뒤 처음 플레이하는 사람의 시도 위치를 관찰한다.

자체 2D 스테이지가 설명에 적합하다. 3D 표현을 추가해도 학습 요인이 늘어나는 경우에는 우선순위가 낮다. 원영상 02:50의 바닥 있는 계단 사이 틈을 앞부분의 낭떠러지와 같은 위험으로 집계하지 않는다. 한 번 낙하해 목숨을 잃는 사건과 잔여 목숨 소진의 게임 오버도 분리한다.

## 한계와 선택

강한 제동·긴 입력 버퍼·관대한 공중 제어는 실패를 줄일 수 있지만 정밀 조작이나 특정 관성의 맛을 바꾼다. 물리 수치 조정이 설명 없는 튜토리얼의 성공을 자동 보장하지 않는다. 구현 API는 캐릭터 이동을 만드는 수단이고, 어떤 행동을 가르칠지는 별도의 레벨 설계다. 세부 이동 주제는 [이동·충돌](../../movement-collision/README.md)에서 다룬다.
