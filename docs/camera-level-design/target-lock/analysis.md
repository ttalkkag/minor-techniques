# 락온: 선택 상태·이동 좌표계·카메라의 일치

[분류 요약](../README.md) · [근거와 조사](research.md)

## 원인

3D 근접 전투에서는 적을 바라보는 조작과 적정 거리를 지키는 조작이 동시에 필요하다. 카메라 방향 기준 이동만 쓰면 카메라를 돌린 순간 같은 좌우 입력의 세계 방향이 바뀐다. 매 프레임 가장 가까운 적을 고르는 방식은 두 적의 거리가 교차할 때 대상까지 바꾸어 입력 기준과 마커를 함께 흔든다.

## 상태를 먼저 정한다

교육용 구현은 자유 상태 → 획득 → 유지 → 전환/해제로 나눈다. 획득 시 거리·화면 위치·가림 조건으로 후보를 고르되, 유지 중에는 동일 대상 ID를 보존한다. 후보 점수가 조금 달라지는 것만으로 대상을 바꾸지 않는다. 전환 버튼이 들어오거나 유지 조건을 벗어났을 때만 상태를 변경한다. 가림 즉시 해제, 짧은 유예 후 해제 중 어느 쪽을 쓸지도 게임 규칙이다.

수평면의 플레이어 위치 p, 대상 q에 대해 `f=normalize(q−p)`를 대상 방향으로 삼고, `r`을 그 방향과 직교하는 수평 단위 벡터로 두면 입력 변위는 `(전후 입력×f + 좌우 입력×r)×속도×Δt`로 설명할 수 있다. 두 입력의 합성 벡터 길이를 1 이하로 제한하지 않으면 두 축을 각각 1로 누를 때 이동 속도가 √2배가 된다. 일정 최고 속도를 원하면 입력 합성 뒤 길이를 제한한다. 대상과 겹쳐 `q−p=0`이면 이전 방향 유지 같은 정책이 필요하다. 높이 차가 큰 대상에는 수평 투영 여부를 명시한다. 이 식은 대상 중심 이동의 자체 모형이며 원작 공식이 아니다.

카메라는 플레이어와 대상의 위치를 함께 고려한다. 두 위치의 중점만 보면 큰 적의 머리나 플레이어 발이 잘릴 수 있으므로 각 대상의 크기도 포함한다. Cinemachine Target Group의 Weight와 Radius는 이 구도 정보를 표현한다. 후보 선정과 이동 규칙은 별도로 구현해야 한다. [공식 Target Group 문서](https://docs.unity3d.com/Packages/com.unity.cinemachine@3.1/manual/CinemachineTargetGroup.html)

## 표시도 같은 상태를 읽는다

선택 마커·카메라·이동은 같은 대상 ID를 사용해야 한다. 적 삭제 뒤 마커가 남거나 카메라만 다음 적으로 넘어가면 플레이어는 잘못된 정보를 받는다. 대상이 사라지면 상태 해제를 먼저 확정하고 표시를 갱신한다. 같은 거리의 두 적, 잠깐 벽 뒤로 숨는 적, 소멸하는 적이 유용한 반례다.

Nintendo 원개발진의 별도 사례로, Kokiri Forest에서는 요정을 먼저 보여 주고 가까워지면 인물을 표시해 존재를 전달했다고 설명한다. 이는 타깃 선택 마커의 역할과 연결되지만 모든 요정이 현재 락온 대상이라는 뜻은 아니다. 사람과 표식의 표시 거리를 분리하는 교육 예로 다룰 수 있다. [Navi 개발자 회고](https://www.nintendo.com/en-gb/Iwata-Asks/Iwata-Asks-The-Legend-of-Zelda-Ocarina-of-Time-3D/Vol-2-Original-Development-Staff-Part-1/4-Where-the-Name-Navi-Came-From/4-Where-the-Name-Navi-Came-From-231748.html)

## 적용 범위

락온은 특정 적과의 거리 유지에 적합하지만 시야 밖 위협 확인이나 다수 적 사이 이동에는 부담을 줄 수 있다. 선택 안정성·화면 이탈·사용자가 원한 대상의 일치를 따로 본다. 위 수식과 상태 조건은 원리 설명 후보이며 실제 조작 평가가 끝난 사양은 아니다.
