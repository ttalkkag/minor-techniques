# 청크 생성과 변경 사항 보존 — 분석

[그룹 요약](../README.md) · [상세 분석](analysis.md) · [리서치](research.md)

## 문제와 원인

카메라 근처만 보이게 하는 것, 메모리에서 청크를 내리는 것, 청크를 처음 생성하는 것, 플레이어의 변경을 저장하는 것은 다른 작업이다. 이를 하나의 ‘삭제’로 구현하면 멀리 갔다 돌아오는 순간 파괴한 벽이 복원된다. 반대로 카메라에서 보이지 않는 청크까지 모두 계속 계산하면 작은 표시 범위에도 메모리와 갱신 비용이 커진다.

## 데이터 흐름

독립 교육용 월드는 기본 지형 함수 `B(seed, generatorVersion, settings, worldPosition)`와 수정 기록 `D(chunk, localCell)`를 분리할 수 있다. 유효한 수정 기록이 있으면 D를, 없으면 B를 읽는다. **빈 블록으로 만든 수정도 기록**해야 한다. 값이 0이라는 이유로 항목을 지우면 ‘수정 없음’으로 되돌아가 원래 벽이 살아난다.

청크 한 변을 `s=16`, 월드 x를 `−1`로 두면 `chunkX=floor(−1/16)=−1`, `localX=−1−(−1×16)=15`다. 정수 절삭으로 chunkX를 0으로 만들면 범위 밖 로컬 좌표가 생기고 이웃 경계가 맞지 않는다.

```text
월드 좌표 → 기본 지형 평가 → 저장된 수정 덮어쓰기 → 메시·충돌 생성
                     ↑                       ↓
              생성 버전·설정              수정 시 dirty 표시
                                             ↓
                                 저장 완료 확인 → 메모리 해제
```

메시·충돌체는 논리 셀 데이터에서 파생된다. 저장된 화면 메시만 복원하면 게임 규칙의 점유 정보와 불일치할 수 있다. 생성 순서가 달라도 같은 위치는 같은 값을 얻도록 세계 좌표 해시 또는 좌표 기반 함수를 사용한다. 하나의 전역 난수열을 청크 요청 순서대로 소비하면 이동 경로에 따라 세계가 달라질 수 있다.

## 해결 절차

1. 생성·상주·표시·시뮬레이션·저장 상태를 별도 필드로 관리한다. 표시를 껐다고 저장 필요성이 사라지지 않는다.
2. 청크 로드 시 저장 버전과 생성 버전을 읽는다. 새 생성기로 기존 수정분을 덮기 전에 기존 바탕 지형과의 호환 정책을 정한다.
3. 공유 경계 샘플은 같은 세계 좌표로 평가한다. 경계 메시가 이웃 셀을 필요로 하면 해당 데이터가 준비될 때까지 상태를 보류하거나 명시적인 임시 경계 정책을 적용한다.
4. 셀 수정으로 논리 데이터와 dirty 상태를 바꾸고 관련 메시·충돌체를 다시 만든다. 경계 셀이면 이웃 청크도 갱신 대상으로 넣는다.
5. 수정 저장이 완료되기 전에 dirty 청크를 버리지 않는다. 재방문뿐 아니라 프로그램 재시작 후에도 수정이 유지되어야 한다.

## 저장 방식 선택

| 방식 | 장점 | 제약 |
| --- | --- | --- |
| 기본 지형 + 수정분 | 수정이 적을 때 작고 생성 원리를 드러냄 | 오래된 생성기가 필요하고 대규모 수정에서는 기록 증가 |
| 전체 청크 스냅샷 | 수정량과 관계없이 한 상태로 복원 | 원래 지형까지 저장하므로 용량·I/O 증가 |
| 혼합 방식 | 수정량에 따라 저장 형태 선택 가능 | 형식 변환·버전 관리 복잡성 추가 |

이 표는 이 프로젝트의 설계 대안이다. Minecraft의 실제 청크 저장 형식을 복원했다는 의미가 아니다. Java 1.18.2의 [공식 변경 기록](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-18-2)은 density function 레지스트리와 noise router를 명시한다. 따라서 영상의 단일 노이즈→높이→동굴 설명을 모든 버전의 고정된 전체 생성 순서로 삼지 않는다.

## 실패가 드러나는 조건

빠른 이동·텔레포트는 생성 작업이 표시 요청을 따라오지 못하는 상황을 만든다. 저장 도중 종료는 최근 수정 보존 정책을 드러낸다. 생성 버전 변경은 이전 D가 새 B에서 엉뚱한 벽을 지우는 충돌을 만든다. 큰 좌표의 정밀도, 파일 쓰기의 원자성, 저장 용량 제한은 좌표 기반 재현만으로 해결되지 않는다.

지형의 형태 계산은 [노이즈 분석](../noise-fields/analysis.md), 경계 면 재생성은 [복셀 메시 분석](../voxel-meshing/analysis.md), 난수 호출 순서는 [RNG 재현 분석](../../game-rules/deterministic-rng/analysis.md)과 연결된다.
