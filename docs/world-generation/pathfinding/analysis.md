# 최단 경로와 다수 유닛 이동 — 분석

## 서로 다른 실패

경로가 최단이 아닌 문제는 탐색 비용과 휴리스틱에서 생긴다. 유닛이 입구에 뭉치는 문제는 이동 충돌과 국소 회피에서 생긴다. 비용장을 공유해 경로 계산 횟수를 줄여도 실제 유닛들이 같은 자리를 동시에 차지할 수는 없다.

## 기준 비용과 A*의 작동

모든 간선 비용이 같은 음이 아닌 값이면 BFS의 최소 단계 경로도 최소 비용 경로다. 음이 아닌 가중치에서는 Dijkstra로 시작점의 누적 비용 `g`가 작은 상태부터 확장한다. A*는 `f(n)=g(n)+h(n)`으로 목표까지의 추정치를 더한다. `h=0`이면 이 우선순위는 Dijkstra와 같다.

휴리스틱이 실제 남은 비용을 넘지 않는 성질이 허용성이다. 여기서는 유한 그래프의 음이 아닌 간선 비용과 `h(목표)=0`을 전제로 한다. 모든 간선 `(u,v)`에서 `h(u)≤cost(u,v)+h(v)`이면 일관성도 만족한다. 허용적이지만 비일관적인 h는 나중에 더 짧은 경로를 발견할 수 있으므로 이미 확장한 노드를 다시 열 수 있어야 한다. 재개방만 추가한다고 과대평가하는 h까지 최적성을 보장받는 것은 아니다. [A* 구현의 비용 완화](https://www.redblobgames.com/pathfinding/a-star/implementation.html), [비일관 휴리스틱 연구](https://cdn.aaai.org/AAAI/2007/AAAI07-192.pdf)

## 재개방이 필요한 작은 반례

다음은 방향 그래프의 교육용 비용이다.

```text
S → A : 3       A → G : 2
S → B : 1       B → A : 1       B → G : 100
h(S)=0, h(A)=0, h(B)=3, h(G)=0
```

B에서 G까지 최저 비용은 3이므로 `h(B)=3`은 과대평가가 아니다. 하지만 B→A에서 `3 > 1+0`이라 비일관적이다.

1. S를 확장하면 A는 `g=3,f=3`, B는 `g=1,f=4`다.
2. A를 먼저 확장해 G 후보 `g=5`를 얻는다.
3. B를 확장하면 A의 더 나은 비용 `g=2`가 발견된다.
4. A를 영구히 닫아 두면 이 개선을 반영하지 못해 비용 5를 반환한다. 다시 열면 A→G를 통해 비용 4를 얻는다.

목표가 발견됐다는 이유만으로 즉시 종료하는 구현도 별도 문제다. 위 조건을 만족하는 A*는 더 나은 g를 반영하고 필요한 재개방을 수행하면서, 목표가 최소 f의 유효한 큐 항목으로 꺼내질 때 종료한다. 이 예시는 알려진 보장 조건을 설명하려고 직접 구성한 것으로 영상의 지도나 실제 게임 동작이 아니다.

## 비용장과 방향장 공유

같은 목표를 향하는 유닛이 같은 이동 규칙을 쓴다면 목표에서 시작한 역방향 탐색으로 모든 위치의 목표까지 비용 `D(u)`를 계산한다. 다음 이동은 `cost(u,v)+D(v)`가 최소인 이웃 v로 고른다. 가중치가 있으면 단순히 D가 가장 낮은 이웃만 고르는 것과 다를 수 있다. 방향 그래프에서는 실제로 u→v로 이동할 수 있어야 하고 역탐색에서도 원래 간선 비용을 보존해야 한다. [목표 공유 플로 필드 구현 설명](https://www.redblobgames.com/pathfinding/tower-defense/)

간선 비용이 모두 양수라면 최적 이동에서 `D(v)<D(u)`가 되어 비용이 계속 줄어든다. 비용 0을 허용하면 최솟값 동점만으로 다음 방향을 정해서는 안 된다. 예를 들어 `A↔B`가 비용 0, `A→G`와 `B→G`가 비용 1이면 `D(A)=D(B)=1`이다. 각자 상대를 고르면 `A→B→A`를 반복할 수 있다. 역방향 Dijkstra에서 확정된 노드를 통해 미확정 이웃의 비용이 엄격히 줄어들 때 다음 노드도 함께 갱신한다. 같은 비용의 후보로 덮어쓰지 않으면 목표에 이르는 탐색 트리를 유지할 수 있다. 도달 불가인 `D=∞`에서는 이동 방향을 만들지 않는다. 이 반례는 위 최소 비용 규칙에서 직접 구성한 것이다.

문이 닫히면 기존 필드가 틀릴 수 있다. 보행·비행·크기가 다른 유닛은 같은 간선을 쓸 수 없으므로 필드를 나누거나 이동 규칙을 포함한 비용 모델이 필요하다. 서로 다른 목표는 필드를 새로 구하거나 공유 범위를 다시 설계한다.

## 해결 절차와 선택

1. 이동 가능 공간과 비용을 정의한다. 격자·NavMesh는 공간 표현이고 BFS·Dijkstra·A*는 그 위의 탐색이다.
2. 작은 지도에서는 Dijkstra 결과를 기준으로 비용을 대조한다. 대각선 허용 여부·음이 아닌 비용·벽 모서리 통과 규칙을 고정한다.
3. A*에 더 나은 g의 반영과 큐 항목 갱신 정책을 둔다. 최단 경로를 보장하려면 h의 허용성을 유지하고, 비일관적인 h에는 재개방을 지원한다.
4. 공통 목표가 충분히 많으면 필드 재사용을 비교한다. 목표 변경·장애물 변경 비용도 포함한다.
5. 경로 이후 국소 회피·가속·반경을 처리한다. 좁은 통로의 혼잡은 탐색 방문 노드 수와 다른 지표로 본다.

[Recast 공식 모듈 구분](https://recastnav.com/)도 Recast의 NavMesh 생성, Detour의 질의, DetourCrowd의 이동·회피를 나눈다. 어느 조합이 더 빠른지는 지도 변화와 유닛 수에 달려 있다. 도달 불가 목표, 시작=목표, 음수 비용, 영구 폐쇄 통로는 각각 다른 처리가 필요하며 탐색 이름 하나로 해결되지 않는다.
